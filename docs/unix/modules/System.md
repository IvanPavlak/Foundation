# System

Machine-wide actions: closing everything, terminal tabs, Wake-on-LAN and reachability, upgrades, drives, theme and wallpaper, languages and keyboard layouts, dated folders, special folders, installed apps, .NET SDKs, machine name, restart, the terminal greeting and the shell profile and its start-up time.

Manifest: [`Unix/modules/System/module.conf`](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/module.conf). One entry per command, alphabetical; the bullet block right under each heading is the parsed part.

## [Determine-DotnetDependencies](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Determine-DotnetDependencies)

- **Description:** Reports which .NET SDKs the projects on this machine need and which are missing, as the Windows Determine-DotnetDependencies does: finds every `*.csproj`, `*.fsproj` and `*.vbproj` under SEARCH-PATH (default the `projects-search-path` line of `Unix/config/dotnet.conf`, else the dev root `$DEV`), skipping paths that contain `node_modules`, `bin`, `obj`, `.git`, `.vs` or `packages` (`--exclude` replaces the list), lists their target frameworks with a project count (`--list-projects` adds the projects), the installed SDKs and runtimes, and the modern versions (net5.0 and later, netcoreapp) without an installed SDK, each with the `brew install dotnet@MAJOR` command and the Brewfile.local line where Windows prints winget and WinGetApps.csv
- **Usage:** `Determine-DotnetDependencies [SEARCH-PATH] [--exclude NAME...] [--list-projects]` (the Windows-style `--exclude-paths` is `--exclude` and `--search-path PATH` a bare SEARCH-PATH)

## [Display-SystemLanguageSettings](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Display-SystemLanguageSettings)

- **Description:** Prints the display languages (`AppleLanguages`, in order), the region (`AppleLocale`, its region and the units, which follow the region unless `AppleMeasurementUnits` is set) and every enabled keyboard layout with its input-source id and the selected one marked, as the Windows Display-SystemLanguageSettings does; each value configured in `Unix/config/language.conf` shows its name there, and the configured defaults close the listing. The layouts come from the input-source driver (`lib/drivers/inputsource.sh`, a Swift helper run by the `swift` of the Command Line Tools). Changes nothing
- **Usage:** `Display-SystemLanguageSettings`

## [Get-InstalledApps](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Get-InstalledApps)

- **Description:** Writes the installed applications to `installed_apps.txt` on the Desktop, as the Windows Get-InstalledApps does from the registry: the Homebrew formulae installed on request (`brew leaves`) and the casks with their versions, the App Store apps (`mas list`), and every app bundle in `/Applications` and `~/Applications` with its version, each under its own heading. A source whose tool is missing is noted in the file. `--output` writes somewhere else
- **Usage:** `Get-InstalledApps [--output PATH]`

## [Invoke-Clear](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Invoke-Clear)

- **Description:** Clears the terminal screen and its scrollback, the first step of Show-TerminalGreeting. Silent when `greeting.conf` has `clear off`, so the greeting draws below what is already on screen
- **Usage:** `Invoke-Clear`

## [Invoke-Fastfetch](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Invoke-Fastfetch)

- **Description:** Draws the fastfetch panel, the second step of Show-TerminalGreeting: this machine type's `FastFetch/Unix/config_<Type>.jsonc` and its text logo, or in WezTerm, Ghostty and kitty the `image-logo` of `greeting.conf` for this machine type when the file exists. It does not clear the screen. The panel is measured first (fastfetch in pipe mode); it overflows when it is wider than the window or taller than the window rows minus one, `fastfetch-prompt-reserve` and `--extra-rows` (the rows printed below it). In WezTerm the font is fitted as Windows Terminal's is: reset to the default on every call (a manual zoom is undone), then shrunk one step at a time while the panel overflows, waiting up to `fastfetch-reflow-timeout-ms` for the window to reflow, until it fits, `fastfetch-max-shrink-steps` is reached or a step changes nothing. The font size is per window, so every tab of the window follows; the steps reach WezTerm as the `FONT_STEP` user variable its `wezterm.lua` answers. A panel that still overflows, and an overflowing panel in any other terminal, is drawn without its logo. `--no-resize` or `fastfetch-auto-fit off` skips measuring and leaves the font alone; `--settle` waits up to 1.5 s for the window to stop resizing. `--prompt-reserve` (0-20), `--max-shrink-steps` (0-50; 0 resets the font and never shrinks) and `--reflow-timeout-milliseconds` (1-10000) override the `greeting.conf` value for one call, a value out of range stopping the command; a `greeting.conf` number out of its range is warned about and replaced by its default (1, 10, 10), as on Windows. `FOUNDATION_STARTUP_SKIP` naming `FastfetchImageLogo` keeps the text logo (the Measure-ShellStartup stage). Silent when `fastfetch off` or fastfetch is missing; `--always` (what a typed bare `fastfetch` runs) draws even with `fastfetch off`
- **Usage:** `Invoke-Fastfetch [--no-resize] [--settle] [--extra-rows N] [--prompt-reserve N] [--max-shrink-steps N] [--reflow-timeout-milliseconds N] [--always]`

## [Invoke-Onefetch](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Invoke-Onefetch)

- **Description:** Shows the onefetch repository panel when the directory is inside a git repository, with the arguments of `Unix/config/greeting.conf`, restyled as it streams (Format-OnefetchPanel): the `onefetch-color` ANSI indices become true-color codes (the last line for an index wins) and the colon after each field becomes `onefetch-separator`, continuation lines re-padded. Keys are case-insensitive and a missing `onefetch` line counts as off, as WinuX's base `Onefetch.Enabled` (the base file ships `onefetch off`; a fork turns it on in `greeting.local.conf`). Silent when onefetch is `off`, not installed, outside a repository or failing; `--measure` prints the panel height (0 when nothing would be drawn or `onefetch-auto-fit` is off). `--arguments` replaces `onefetch-arguments` for one call: every word after it is onefetch's (or one quoted string of them), so it comes last (`Invoke-Onefetch --arguments --no-art`). `--always` is what a typed `onefetch` runs: it ignores `onefetch off` and the repository check, and onefetch's own error and exit status come through. `FOUNDATION_STARTUP_SKIP` naming `OnefetchStyle` prints onefetch's output unstyled (the Measure-ShellStartup stage)
- **Usage:** `Invoke-Onefetch [--measure] [--path DIR] [--always] [--arguments ARGS...]`

## [Kill-All](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Kill-All)

- **Description:** Focuses desktop 1 (the VirtualDesktops step: AeroSpace workspaces vanish when emptied, so there is nothing to remove), stops Docker (running containers, then Docker Desktop), quits browsers, every app with a window (except the `keep` apps, Finder and the terminal: the `Terminal` role is never quit, since Kill-All runs in it; with no `keep` line at all the step warns and quits nothing, as Windows does without exclusions) and the `quit` apps of `Unix/config/kill-all.conf` (a `quit` token `apps.conf` does not know is taken as a bundle id, and when no app answers to it, as a process by its exact name - a daemon or helper - ended with `pkill`, then `pkill -9` after 5 s, as Terminate-AllProcessesByName does; no `quit` line at all is a warning), then closes the other terminal tabs, focuses this terminal (the MoveTerminal step, off by default, first moves it to desktop 1; skipped with `--include-current`) (it stays tiled full size; the CenterTerminal step, off by default on Unix, centers it instead with `--include CenterTerminal`). Cmd+Q semantics; an app of VisibleWindows or NamedProcesses that ignores it is killed after 5 s, as Windows force-kills them. Browsers are never killed, as on Windows: a browser still running 4 s after the quit request is asked once more, and one still running 2 s later is named with its windows in a warning ("did not quit (a dialog may be waiting for an answer)") and left running; the step then ends without its success line. When the Browsers, VisibleWindows and NamedProcesses steps all ran, the windows still open are audited as by the Windows Report-KillAllSurvivors: every window AeroSpace lists except the `keep` apps, the terminal, Finder and `--exclude` matches is reported as "Title (App, PID n)", and the run ends with a warning instead of the success line (exit status 0; a survivor is usually a dialog waiting for an answer). `--exclude` keeps matching windows (their app's other windows are closed one by one); a pattern is an app token or name (`Claude`, `Code`), a title wildcard (`*YouTube*`) or a regex. Like on Windows the patterns may come first without the flag and as a comma list (`Kill-All Claude,Code`). `--skip`/`--include` override a step of `kill-all.conf` for one run; a step named in both is skipped, with a warning, as on Windows. A step with no line anywhere behaves like the base file's line (on, except MoveTerminal, CenterTerminal and ReloadProfile). The ReloadProfile step (off by default; `--reload-profile`) cannot reload the calling shell from a child process, so it only prints a hint to run `Reload-Profile`. Clears the Close-Workspace record (every instance) only when the Browsers, VisibleWindows and NamedProcesses steps all ran, as on Windows: a partial run keeps it, so the windows that survived stay closable. A flag it does not know (a typo, `-WhatIf`) stops it before anything is closed, as on Windows. A step name of `--skip` or `--include` that is none of its steps stops it before anything closes, as the Windows ValidateSet does.
- **Usage:** `Kill-All [PATTERN...] [--exclude PATTERN...] [--skip STEP...] [--include STEP...] [--include-current] [--reload-profile]`

## [List-Drives](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/List-Drives)

- **Description:** Lists the startup volume and the mounted volumes under `/Volumes` with size, used and free space and use percentage; the Recovery and APFS helper volumes are left out
- **Usage:** `List-Drives`

## [Measure-ShellStartup](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Measure-ShellStartup)

- **Description:** Times the interactive shell start stage by stage, as the Windows Measure-ShellStartup does. `Unix/shell/shellrc.sh` runs its optional parts as stages (LineEditing, Aliases, Prompt, Plugins, Icons, Greeting, RepositoryUpdate) that `FOUNDATION_STARTUP_SKIP` (`WINUX_STARTUP_SKIP` on Windows; names in any case, separated by commas, semicolons or spaces) leaves out and that write their own time to the file `FOUNDATION_STARTUP_TRACE` names; FastfetchImageLogo and OnefetchStyle, walked after Greeting as on Windows, are the image logo and the onefetch restyle the greeting commands leave out. After one uncounted warm-up, each configuration starts `SHELL -i -c exit` N times (`--runs`, 1-50, default 5; `--shell`, default `$SHELL`) and shows min / median / max in milliseconds (the median of an even count is the mean of the two middle values, as on Windows), the Delta and the stage's InShell median. The default walk is additive (`--mode Cumulative`: a bare row with no rc file for zsh or bash, Core with every stage left out, then one more stage per row); `--leave-one-out` (`--mode Isolated`) starts from Full and leaves one stage out per row. `--stages` walks only the named stages, in the order given (the others stay out of every additive row); `--pass-thru` prints the rows as tab-separated values with a header instead of the table. The shells draw nothing and cannot reach this terminal, but the stages run for real (a RepositoryUpdate that is due runs)
- **Usage:** `Measure-ShellStartup [--runs N] [--mode Cumulative|Isolated] [--leave-one-out] [--stages NAME...] [--shell PATH] [--pass-thru]` (the Windows-style `--additive` is the default mode, accepted)

## [Reload-Profile](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/functions.sh)

- **Description:** Shell function: reloads the Foundation modules and the shell configuration by replacing this shell with a fresh login shell, then lists every reloaded module. The `Reload-PowerShellProfile` analog; Kill-All's ReloadProfile step points at it
- **Usage:** `Reload-Profile`
- **Alias:** `reload-profile`

## [Rename-Machine](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Rename-Machine)

- **Description:** Sets the Mac's ComputerName, HostName and LocalHostName (spaces become hyphens) through scutil. Does nothing when the current name already is a `host` of `Unix/config/machines.conf`, unless `--override`; without NAME offers a menu of the configured names whose last entry, `Enter new name`, asks for a new one (an empty name cancels). The host name (spaces hyphenated) must follow the Windows naming rules - at most 63 characters, only letters, digits and hyphens, not digits alone - and is checked before any scutil call, so a rejected name never leaves the Mac half renamed: a typed name that breaks them is asked again, a NAME argument stops the command. Asks for the administrator password. A flag it does not know is an error, never taken for NAME.
- **Usage:** `Rename-Machine [NAME] [--override]` (the Windows-style `--name NAME` works too)

## [Restart-Machine](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Restart-Machine)

- **Description:** Asks for confirmation, then restarts the Mac through System Events like the Apple menu does, so apps can save (and an app with unsaved work can still cancel); `--force` skips the confirmation. Any other argument is an error. A yes is followed by a 5-second countdown, as on Windows (Ctrl+C cancels the restart); `--selection Yes|No` (the Windows `-Selection`, which also takes the menu numbers `1` for Yes and `2` for No) answers the prompt, Yes still counting down; `--force` skips both. `FOUNDATION_RESTART_COUNTDOWN` sets the seconds (0: none). It asks through the shared Yes/No menu (Enter means No) on the terminal, never stdin, so a piped answer never restarts and a run without a terminal cancels.
- **Usage:** `Restart-Machine [--force | --selection Yes|No]`

## [Send-WakeOnLan](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Send-WakeOnLan)

- **Description:** Sends a Wake-on-LAN magic packet to machines of `Unix/config/wake-on-lan.conf`. Without a name a menu of the machines, then All (every machine) and None (cancel), is shown, and an empty Enter wakes the `default` machine (nothing when there is none), as on Windows. All and None may also be given as names, in any case, as `-Machine None` does on Windows: `w MyWorkspace --machine None` opens the workspace and wakes nothing. A workspace action without a name and without a terminal wakes the `default` machine. A machine with an `address` is skipped when it already answers a ping and is then pinged until it wakes (`--timeout-seconds`, default 120); a machine without one gets a warning that its wake cannot be confirmed. `--no-wait` sends and verifies nothing, the already-online ping included, as on Windows. A flag it does not know is an error, never a machine. A machine given as a number is that entry of the menu, All and None included (`Send-WakeOnLan 2`).
- **Usage:** `Send-WakeOnLan [MACHINE[,MACHINE...]...|All|None] [--all] [--timeout-seconds N] [--no-wait]` (the Windows-style `--machine` is accepted and ignored)

## [Set-DisplayLanguage](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Set-DisplayLanguage)

- **Description:** Sets the display language to a `display-language` of `Unix/config/language.conf`, as the Windows Set-DisplayLanguage does: without a name a menu of them is shown, where Enter picks `default-display-language`. `AppleLanguages` becomes that language followed by the other configured display languages (the fallbacks), and the language part of `AppleLocale` follows it while the region stays. Nothing changes when the language is already first or none is configured. Takes full effect after logging out and back in
- **Usage:** `Set-DisplayLanguage [NAME | --language NAME]`

## [Set-KeyboardLayouts](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Set-KeyboardLayouts)

- **Description:** Applies a `keyboard-set` of `Unix/config/language.conf` (an ordered list of `keyboard-layout` names, each an input-source id such as `com.apple.keylayout.Croatian-PC`), as the Windows Set-KeyboardLayouts does: without a name a menu of the sets is shown, where Enter picks `default-keyboard-set`. The set's layouts are enabled, the first is selected and every other enabled keyboard layout is disabled, live with no logout, through the input-source driver (`lib/drivers/inputsource.sh`); input methods such as the Character Palette stay. Nothing changes when exactly those layouts are enabled with the first selected, unless `--override`, or when no set is configured; a layout the Mac does not have fails before anything changes
- **Usage:** `Set-KeyboardLayouts [SET | --layout-set SET] [--override]`

## [Set-Locale](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Set-Locale)

- **Description:** Sets the region (date, number and unit formats) to a `locale` of `Unix/config/language.conf`, the Set-Culture and Set-WinHomeLocation of the Windows Set-Locale: without a name a menu of them is shown, where Enter picks `default-locale`. The region of the locale's code (`hr-HR` is HR) goes into `AppleLocale` as System Settings writes it, the display language with `@rg=<region>zzzz` (`en_US@rg=hrzzzz`), or the language alone when its own country is the region; the units follow the region. Nothing changes when the region already matches or no locale is configured. Apps opened afterwards use the new formats
- **Usage:** `Set-Locale [NAME | --locale NAME]`

## [Set-SpecialFolders](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Set-SpecialFolders)

- **Description:** Redirects Downloads and the screenshot folder as `Unix/config/special-folders.conf` says, the SpecialFolders of Windows. `folder Downloads PATH` turns `~/Downloads` into a link to PATH, so every app that saves to Downloads saves there; what `~/Downloads` holds moves to PATH first, and a name PATH already has is never overwritten (the moved item is kept as `NAME (Downloads)`); the `group:everyone deny delete` rule macOS puts on `~/Downloads` is then removed from the emptied folder (`chmod -N`) so the link can take its place. To undo: `rm ~/Downloads && mkdir ~/Downloads && chmod +a "group:everyone deny delete" ~/Downloads` and drop the line. The first run asks for the terminal's access to the Downloads folder. `folder Screenshots PATH` sets `com.apple.screencapture location`. Nothing is redirected without a line, nothing is undone when a line goes; `--dry-run` changes nothing. Bootstrap runs it as the SpecialFolders step
- **Usage:** `Set-SpecialFolders [--dry-run]`

## [Set-SystemTheme](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Set-SystemTheme)

- **Description:** Switches the macOS appearance to Dark or Light (`Toggle` flips it; without a theme or `--auto` it applies Dark, as on Windows) through System Events, then runs the follow-up steps of `Unix/config/theme.conf`: SetWallpaper (Set-Wallpaper for the new theme, on by default). `--auto` takes this machine type's `theme` line and leaves the system as it is without one; `--skip`/`--include` override a step for one run, `--skip` wins. A step name other than SetWallpaper, or a flag it does not know, stops it before anything changes.
- **Usage:** `Set-SystemTheme [Dark|Light|Toggle] [--auto] [--skip STEP[,STEP...]...] [--include STEP[,STEP...]...]` (the Windows-style `--theme THEME` and `--keep-terminal-open` work too)

## [Set-Wallpaper](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Set-Wallpaper)

- **Description:** Sets the wallpaper of every display from `Unix/config/wallpapers.conf`: the `[Dark]` or `[Light]` line of this machine type, else `Default`; several files go to the displays in order and cycle, and a path with spaces is double-quoted. Auto (default) follows the system appearance; `--dry-run` only prints the plan. A bare THEME works as `--theme`; `--auto` is accepted and changes nothing (it does not override `--theme`): on Windows it skips the interactive wallpaper picker, which Foundation does not have (the wallpaper comes from configuration, System Settings covers a manual pick), so every call already runs the way `-Auto` does
- **Usage:** `Set-Wallpaper [THEME] [--theme Light|Dark|Auto] [--auto] [--dry-run]`

## [Show-TerminalGreeting](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/functions.sh)

- **Description:** Shell function: the greeting every new shell draws and `c` redraws, in three steps `greeting.conf` switches on and off: Invoke-Clear, Invoke-Fastfetch, then the onefetch panel inside a git repository (Invoke-Onefetch). Onefetch is measured first and its height passed to Invoke-Fastfetch as `--extra-rows`, so fastfetch drops its logo when both panels together would not fit. `--no-clear`, `--no-fastfetch` and `--no-onefetch` skip one step for this call (the measurement goes with `--no-fastfetch`, `--no-onefetch` and `--no-resize`); `--no-resize`, `--settle`, `--prompt-reserve`, `--max-shrink-steps` and `--reflow-timeout-milliseconds` go to Invoke-Fastfetch (`c --max-shrink-steps 0` shows whether the panels fit at the default font). Flags match case- and dash-insensitively, as PowerShell binds them (`c -NoOnefetch`); an unknown word is warned about and ignored, so the greeting still draws. A new shell draws it whatever is installed, each step skipping itself when its tool is missing. A typed `fastfetch` or `onefetch` (shell functions of `Unix/shell/shellrc.sh`, as the Windows all-hosts profile defines them) looks like the greeting: a bare `fastfetch` is `Invoke-Fastfetch --no-resize --always`, `onefetch` is `Invoke-Onefetch --always` with the call's arguments as `--arguments`; `fastfetch` with arguments, and either one without its tool, is the tool itself. Project tabs opened by `w` draw it once their window is placed
- **Usage:** `Show-TerminalGreeting [--no-clear] [--no-fastfetch] [--no-onefetch] [--no-resize] [--settle] [--prompt-reserve N] [--max-shrink-steps N] [--reflow-timeout-milliseconds N]`
- **Alias:** `c`, `show-terminalgreeting`

## [Terminate-WindowsTerminalTabs](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Terminate-WindowsTerminalTabs)

- **Description:** Closes every WezTerm tab except this one, each with all of its panes, keeping this tab whole (a split pane next to this one stays), and warns when a tab of the pass is still open afterwards ("the cleanup left N tab(s) open"), as Windows checks for leftovers; `--include-current` closes this tab too (its other panes, then this one, last), `--only-current` only this pane, then refocuses the desktop that was focused (closing a tab raises the WezTerm window, and AeroSpace would follow it). "This tab" is the WezTerm pane whose tty is the command's terminal: run from outside a WezTerm pane (an app started from WezTerm inherits `WEZTERM_PANE`), `--only-current` closes nothing and no tab is spared. `--close-wait-seconds N` (0-300, the Windows `-CloseWaitSeconds`) counts down N seconds (Countdown; Ctrl+C keeps the tab) before this tab closes, so its last output can be read. Name kept from Windows. Any other argument is an error and closes nothing.
- **Usage:** `Terminate-WindowsTerminalTabs [--include-current | --only-current] [--close-wait-seconds N]`

## [Test-MachineOnline](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Test-MachineOnline)

- **Description:** Pings a machine of `Unix/config/wake-on-lan.conf` at its `address`, or any IP address or hostname, once or with `--wait-for-online` until it answers or `--timeout-seconds` (120) pass. Exit status 0 when online, 1 otherwise (also for a configured machine without an address); Send-WakeOnLan shares its ping helpers. `--machine` and `--address` name the target as the Windows `-Machine` and `-Address` do, and `--display-name NAME` is the name its messages use. `--interval-seconds` (default 3, as on Windows) is the pause between the pings of a wait and `--ping-timeout-milliseconds` (default 1000) how long one ping waits, rounded up to whole seconds. A flag it does not know is an error, never the target.
- **Usage:** `Test-MachineOnline MACHINE|ADDRESS|--machine MACHINE|--address ADDRESS [--wait-for-online] [--timeout-seconds N] [--interval-seconds N] [--ping-timeout-milliseconds N] [--quiet] [--display-name NAME]`

## [Update-DirectoryNames](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Update-DirectoryNames)

- **Description:** Renames every folder directly under PATH (default the current folder) whose name ends in `_YYYY_MM_DD` to end in today's date instead (`Report_2026_01_31` becomes `Report_2026_10_22`), as the Windows Update-DirectoryNames does; a name that is only a date becomes today's date. A folder already dated today is left alone, and so is one whose new name is taken (the run then fails). `--dry-run`, the `-WhatIf` of Windows, prints what would be renamed and renames nothing
- **Usage:** `Update-DirectoryNames [PATH] [--dry-run]` (the Windows-style `--path` is accepted and ignored)

## [Upgrade-All](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/System/bin/Upgrade-All)

- **Description:** Upgrades the named package managers, Homebrew and AppStore by default (as the Windows Upgrade-All upgrades every manager in use). Homebrew: the pinned formulae (`brew pin`) are listed and skipped (the Show-PinnedAppsWarning analog), then `brew update` and `brew upgrade`; casks that update themselves are left to it. AppStore: `mas outdated` lists the apps with an update and only then `sudo mas upgrade` runs (mas needs the administrator password to upgrade); without mas it is skipped with a warning. `MacOS` installs pending system updates through `softwareupdate` (asks for the administrator password, may restart) and runs only when named. Every named manager is checked before the first one runs (the ValidateSet of Windows): an unknown manager or flag upgrades nothing.
- **Usage:** `Upgrade-All [Homebrew|AppStore|MacOS[,...]...]` (the Windows-style `--package-manager` is accepted and ignored)
