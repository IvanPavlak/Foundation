# Window

Desktops (AeroSpace workspaces), window lookup and inspection, moving, centering and resizing windows, workspace layouts and their drawings.

Manifest: [`Unix/modules/Window/module.conf`](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/module.conf). One entry per command, alphabetical; the bullet block right under each heading is the parsed part.

## [Center-Terminal](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Center-Terminal)

- **Description:** Centers the WezTerm window on the primary display at a physically constant size: the `center-terminal` target of `Unix/config/window.conf` (CenterTerminalSizing, 1376 x 700 by default; the SmallDisplay row on a small primary display, else the row of the layout machine type - `layout-override`, then `small-display`, then the machine type, the Get-LayoutMachineType of Windows - else Default, as on Windows) becomes shares of the live work area clamped to its percent bounds and then into Center-Windows' 10-100, then Center-Windows floats and centers WezTerm. When the work area cannot be read it hands Center-Windows its own 40 x 50, as Windows does without monitor data. Kill-All's CenterTerminal step runs it and skips quietly without the Accessibility permission
- **Usage:** `Center-Terminal`

## [Center-Windows](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Center-Windows)

- **Description:** Floats every matching window (all by default, `--current` for the focused desktop; `--process` app token, role or name and `--window-title`, the Get-WindowHandle rules: given both, a window matching either, as on Windows) out of AeroSpace's tiling and centers it on the primary display at `--width-percent` (40) by `--height-percent` (50) of the work area, whole numbers from 10 to 100 (the ValidateRange of Windows; anything else is an error before a window is touched). The frame is set through the Accessibility API, so the terminal must be allowed in System Settings > Privacy & Security > Accessibility (the command says so when it is not), on the window AeroSpace listed: the Accessibility API does not know AeroSpace's window id, so the window of the app whose frame the window server reports for that id is the one set, and two same-titled windows (two `New Tab` Chrome windows) are each centered; `Reset-Windows --current` tiles them again. Each desktop holding a matching window is shown while its windows are floated and centered, because AeroSpace parks a hidden desktop's windows in a corner and puts a floating one back where it remembers once the desktop is shown; the desktop focused before comes back at the end, and a desktop AeroSpace does not show counts its windows as not centered. `--on-primary` and `--monitor M` (the Windows flags) are accepted and ignored: windows are always centered on the primary display. A window it could not center is reported, and the run then ends with a warning and exit status 1 instead of the success line.
- **Usage:** `Center-Windows [--width-percent N] [--height-percent N] [--process | --process-name PATTERN] [--window-title PATTERN] [--current] [--on-primary] [--monitor M]`

## [Focus-VirtualDesktop](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Focus-VirtualDesktop)

- **Description:** Switches to desktop NUMBER (1-based, the AeroSpace workspace alt-NUMBER shows). NUMBER is a whole number from 1 to 100 and `--desktop-offset N` (alongside opens) shifts it; anything else is an error before any switch. As on Windows it prints `[Focusing Virtual Desktop N]`, parks the focus on the terminal (the first window of the `Terminal` role of `apps.conf`) when one is on that desktop, else leaves AeroSpace's last-focused window there, and ends with `Focused Virtual Desktop N!`, or warns `Switched to Virtual Desktop N, but found no window to focus!` when the desktop is empty (still exit 0). N is the desktop focused, the offset included; a switch AeroSpace refuses fails the command.
- **Usage:** `Focus-VirtualDesktop [NUMBER | --desktop-number NUMBER] [--desktop-offset N]`

## [Get-ActiveWindowInfo](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Get-ActiveWindowInfo)

- **Description:** Prints every window AeroSpace manages, or those whose title matches PATTERN (wildcard, regex or exact, as in the layout files), for writing layouts, as the Windows Get-ActiveWindowInfo does: the app with its bundle and PID, the window id and desktop, the frame (x, y, width, height in points, read from the window server by window id, so same-titled windows each show their own, and no permission is needed) and a ready-to-paste layout line, `DESKTOP Zone APP TITLE`, with `Zone` a placeholder to replace. `--continuous` watches the focused window instead and prints a block each time focus moves to another (matching) window, until Ctrl+C. Prints to the terminal only, where Windows also writes `ActiveWindowInfo.txt` to the Desktop; redirect it or pipe it to `pbcopy`
- **Usage:** `Get-ActiveWindowInfo [PATTERN] [--continuous]` (the Windows-style `--window` is accepted and ignored)

## [Get-WindowHandle](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Get-WindowHandle)

- **Description:** Lists managed windows (id, app token, workspace, title, then the PID and the frame - x, y, width, height in points, read from the window server by window id in one read, no permission needed, empty when unreadable - appended so the first four tab-separated columns keep their place when piped), optionally filtered by app (an `apps.conf` token, a role such as `Browser`, or the app name) and/or title pattern with the Windows matching rules (exact, wildcard, regex; case-insensitive; an exact app name always matches, `notepad++` included, a title pattern may start with `(?i)`, and one POSIX regex rejects is matched as plain text); given both, a window matching either is listed, as on Windows. Move-Windows, Center-Windows and Resize-Windows select their windows by the same rules, so it previews what they act on; its id is what `Resize-Windows --window-handle` takes
- **Usage:** `Get-WindowHandle [--process-name PATTERN] [--window-title PATTERN]` (the Windows-style `--all` is accepted and ignored)

## [Move-Windows](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Move-Windows)

- **Description:** Moves every matching window (all by default; `--process` app token, role or name, `--window-title`, the Get-WindowHandle rules: given both, a window matching either, as on Windows) to desktop N (`--desktop`, `--virtual-desktop` or a bare number; a whole number from 1 to 100, the ValidateRange of Windows; an AeroSpace workspace, default 1, created on first use) or with `--current` to the focused one, then focuses it; pure AeroSpace, no permission needed. A window AeroSpace refuses to move is counted, and the run then ends with `N window(s) could not be moved to desktop D` and exit status 1 instead of the success line (the others still move and the target is still focused), as Windows warns. `--monitor M` is accepted and ignored with a warning: only one display is managed on macOS yet. A bad desktop or a flag it does not know is an error before any window moves.
- **Usage:** `Move-Windows [--desktop | --virtual-desktop N | N | --current] [--process | --process-name PATTERN] [--window-title PATTERN] [--monitor M]`

## [Reset-Windows](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Reset-Windows)

- **Description:** Retiles the desktops into a clean, balanced state the AeroSpace way. Windows needs a clean slate before a layout; AeroSpace does not (`w <Workspace>` lays windows out from any state), so the reset happens in place: on every desktop (`--desktop N` or `--current`: only that one) floating windows go back into the tiling, the tree is flattened into one row and the tiles are balanced; windows stay on their desktops. Each desktop is shown while it is retiled (AeroSpace changes the layout of a window on a hidden desktop only once it is shown) and the desktop focused before comes back at the end; a desktop AeroSpace refuses is reported and fails the run. `--gather N` first moves every window to desktop N, the Windows behaviour; a window that cannot be moved there stops the run before anything is retiled. `--virtual-desktop N` or a bare number is `--desktop N`; `--center` and `--monitor M` (the Windows flags) are accepted and ignored with a warning, having no AeroSpace counterpart. A desktop is a whole number from 1 to 100; a bad desktop or a flag it does not know is an error before anything changes. A named desktop (`--desktop`, `--current`) without a window is reported and the exit status is 1.
- **Usage:** `Reset-Windows [--desktop | --virtual-desktop N | N | --current] [--gather N] [--center] [--monitor M]`

## [Resize-Windows](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Resize-Windows)

- **Description:** Scales matching windows (`--process` app token, role or name, `--window-title`, the Get-WindowHandle rules: given both, a window matching either, as on Windows) by `--percent` or a bare number (a whole number from 10 to 500, the ValidateRange of Windows; 100 leaves them, below shrinks, above enlarges) around their center, kept at least 100 points a side and clamped to the work area, as on Windows. `--window-handle ID` keeps only the window of that id (Get-WindowHandle lists it). Without `--percent` the `resize-windows` row of `Unix/config/window.conf` applies, resolved as the Windows `ResizeWindowsPercent`: `SmallDisplay` (a primary display at most `small-display-width` points wide), then the layout machine type (`layout-override`, then `small-display`, then the machine type), then `Default`; a fraction is rounded (33.5 gives 34), and a missing row, a value that is not a number or one outside 10-500 gives 70. A tiled window is floated first, because a tile always fills its slot: resizing it under AeroSpace only moves the split to the neighbour and cannot change the height (measured on AeroSpace 0.21.3; a Firefox tile asked for 450 pt stayed 500 pt, its minimum, and ran off screen). The frame is read while the window is still tiled, because a window AeroSpace floats gets back its last floating size instead of the tile's. Floating frames hold exactly - Center-Windows 50 x 60 % and a following 80 % resize matched the computed frames to the point and stayed put. Reset-Windows (or `Reset-Windows --current`) tiles them again. Each window's frame is read from the window server by its window id and set through the Accessibility API on that same window (found by its frame), so same-titled windows of one app are each scaled once; setting needs the terminal to be allowed in System Settings > Privacy & Security > Accessibility, and without it the run stops at the first window. Each desktop holding a matching window is shown while its windows are measured and resized (AeroSpace parks a hidden desktop's windows in a corner, so neither their frame nor a new one would hold), the desktop focused before comes back at the end, and a desktop AeroSpace does not show counts its windows as not resized. A window it could not read or resize is reported, and the run then ends with a warning and exit status 1 instead of the success line.
- **Usage:** `Resize-Windows [--percent N | N] [--process | --process-name PATTERN] [--window-title PATTERN] [--window-handle ID] [--current]`

## [Set-WorkspaceWindowLayout](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Set-WorkspaceWindowLayout)

- **Description:** Waits for the windows of a workspace's layout (`Unix/config/layouts/<TYPE>/<WORKSPACE>_<TYPE>.conf`) and tiles each desktop, printing what Windows prints: the `[Applying WORKSPACE Workspace Layout]` title, one `Applying layout` spinner over the wait and the arrangement (warnings held until it stops; the per-desktop detail only with `-v`) and `Workspace layout applied successfully!`, followed, as on Windows, by the Visualize-Layouts drawing of the applied layout. Without a WORKSPACE (and without `--layout-path`) it applies `Fullscreen`, as on Windows. Windows are waited for up to `--timeout-seconds` (default 60, as on Windows; Open-Workspace passes 60 too). Each entry claims one window once its title and its frame have held for `layout-stable-ms` of `workspaces.conf` (500 in the base and without the line; `FOUNDATION_STABLE_MS` overrides it; the frame as Windows' stable dimensions, so a window still restoring its bounds is not placed mid-resize, and a frame that cannot be read leaves the title alone to decide), waiting up to `--timeout-seconds` (60, or `FOUNDATION_LAYOUT_TIMEOUT`, which Open-Workspace sets). As Windows' remembered-window pins, an Applied open records the window each entry held (`$XDG_STATE_HOME/foundation/layout-pins/<workspace>_<set>`) and a rerun gives every entry that window back when it is still there and still matches; an entry without one prefers a window already on its own desktop, so identical windows (many Browser entries, same-titled VS Code windows) keep their zones and desktops; when a browser entry's title matches no live window (its window shows another tab than the group's first), every unprotected browser window that no titled browser entry matches is switched to its first tab before the wait (focused, Cmd+1, as Ctrl+1 on Windows; needs the Accessibility permission), and the focus is put back; an entry that never held a window is given up after `layout-absent-grace-seconds` of `workspaces.conf` (10 in the base and without the line, 0 waits the whole timeout; the Windows `ProcessAbsentGraceSeconds`) when every window matching it is one the open may not take (another workspace's protected window, or a pre-existing one under `--alongside`), or when no window of its app is listed and none of its `apps.conf` bundles is running, so a missing app costs the grace period instead of the timeout (an app pattern naming no `apps.conf` bundle is waited for); `--disable-auto-wait` (the Windows `-DisableAutoWait`) takes one look instead, each entry claiming what matches at once with no title to hold, and a window that is not there yet stays unplaced. `--layout-path FILE` (the Windows `-LayoutPath`) applies a layout file from anywhere: its only workspace, or the one WORKSPACE names; the layout set recorded is `--layout-type`, else the name of the file's folder. It tiles each desktop: strays parked on the `parking-workspace` of `zones.conf` (P), windows ordered left to right and sized to the zone set's column shares, halved columns (Top-/Bottom- zones) built as vertical containers, the windows sharing a zone (a whole desktop, a column, or a top or bottom half) stacked as an accordion with the last entry in front (Set-StackedWindowOrder); an entry without a title never takes a window a titled entry of the same app asks for, and the only untitled entry of an app takes every remaining window of it (the catch-all of Get-LayoutProcessSiblings). Each desktop is then read back (Confirm-WorkspaceWindowPositions): every window must be on its desktop and within 50 points of its zone (one read of the window server's window list per desktop, by window id, so windows of one app with the same title, such as several `New Tab` browser windows, each get their own frame; it needs no permission); while one is misplaced the desktop is arranged again, up to two more times, and then the open ends Partial with the Expected / Actual frame of each misplaced window. During a workspace open the most passes one desktop needed is the layout's Attempts in the benchmark row (1 at the first try, as Windows' Attempts; the `retries N` of the Timing line). A window whose frame cannot be read is checked only for its desktop. `--project NAME...` (Open-Workspace passes the open's projects) applies the layout file's `project` variants, several in the order given; a variant naming an unknown project is reported and skipped. Primary monitor only. With `layout-early-move on` (`workspaces.conf`, the Move-StableWindowEarly idea) each window moves to its desktop the moment it is claimed, while the other apps are still starting; AeroSpace's static `on-window-detected` rules cannot do this, because one app goes to different desktops in different workspaces. A workspace named in `simple-layouts` of `workspaces.conf` (Fullscreen, Empty - the SimpleLayoutWorkspaces of Windows) is a global gesture instead: every window on every desktop goes full size as one accordion per desktop, no window changes desktop, and `Reset-Windows` or `alt-/` tiles a desktop again. Each desktop is shown while its accordion is set (AeroSpace changes the layout of a window on a hidden desktop only once it is shown) and the desktop focused before comes back; a desktop AeroSpace refuses ends the open Partial. During a workspace open the windows of other workspaces the open protects (a plain open: live alongside workspaces; an alongside open: every other one) are never claimed or parked; `--alongside` takes only the windows the open created and `--desktop-offset N` puts every desktop of the layout N desktops to the right. A flag it does not know (the `-SnapDelayMs` or `-PrepareOnly` of Windows) is an error before a window is placed. The zones follow AeroSpace's gaps (`Unix/aerospace/aerospace.toml`: 3 points between windows in the base file, as the FancyZones spacing on Windows, and none at the screen edges): the column widths and the expected frames are computed from whatever inner and outer gaps that file sets. Desktops are arranged once every window has appeared, not desktop by desktop while the rest are still awaited (Windows' WorkspaceLayoutPipelining is not ported): the benchmark of 2026-10-23 shows the Example workspace waiting about 1.9 s against 9-12 s of arranging, so overlapping the two would save at most the wait. It is worth revisiting if the wait grows to dominate an open.
- **Usage:** `Set-WorkspaceWindowLayout [WORKSPACE | --workspace-name WORKSPACE | --layout-path FILE] [--project NAME...] [--timeout-seconds N] [--disable-auto-wait] [--layout-type TYPE] [--alongside] [--desktop-offset N] [-v]`

## [Visualize-Layouts](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Window/bin/Visualize-Layouts)

- **Description:** Draws each desktop of a workspace's layout (`Unix/config/layouts/<Type>/<Workspace>_<Type>.conf`) as its zone set of `zones.conf`, proportional columns and halved columns included, with the app and title of every window assigned to each zone, then each `project` variant as the desktops it changes look with it applied; a variant naming a project `projects.conf` does not have is reported and not drawn, as Set-WorkspaceWindowLayout reports and skips it. `--layout NAME` is the Windows spelling of a WORKSPACE name. A menu of the workspaces without a name, `--all` for every one of every layout set (with `--layout-type`, of that set only; Windows' `-All` covers every machine type too, so `--all --update` refreshes every set's drawings), `--layout-type` for another machine type's set, `--display-available-layouts` for every zone set with its zone names. `--update` writes each drawing into its layout file as `#|` comment lines under the section header (replacing the previous ones) after copying the file into the backup sink (`Backups/Unix/Config/WindowLayouts.<Type>.<Workspace>/<timestamp>/`; `--backup-root DIR`, the Windows `-BackupRoot`, puts it under `DIR/Config/` instead). `--layout-path FILE` (the Windows `-LayoutPath`) draws every workspace of one file from anywhere, its set for the backup key being `--layout-type` or the name of the file's folder; it takes no workspace name and no `--all`. A layout with errors (a desktop on an unknown zone set, a zone not in its desktop's zone set, a desktop with windows but no layout line, an app that is no `apps.conf` token or role - the Test-ConfigurationSchema check, `layout_entry_problems`, run on the base and on each variant that applies) is reported and neither drawn nor updated, as Windows' Validate-Layout skips it. A requested layout that does not exist, or one skipped for errors, is reported, the others are still drawn, and the exit status is 1; a flag it does not know is an error, never a workspace.
- **Usage:** `Visualize-Layouts [WORKSPACE[,WORKSPACE...]... | --layout NAME | --layout-path FILE] [--all] [--layout-type TYPE] [--display-available-layouts] [--update] [--backup-root DIR]`
