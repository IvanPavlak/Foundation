# Application

Launches and focuses applications and browser groups.

Manifest: [`Unix/modules/Application/module.conf`](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/module.conf). One entry per command, alphabetical; the bullet block right under each heading is the parsed part.

## [Deploy-VSCodeProfiles](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Deploy-VSCodeProfiles)

- **Description:** Deploys the VS Code profiles `Unix/config/vscode-profiles.conf` selects for this machine type (its last `deploy` line), or the named catalogue entries, as the Windows Deploy-VSCodeProfiles does. First, every local extension under `extensions` (`VSCode/Extensions`: one unpackaged extension folder with a `package.json` each, such as a colour theme of your own) is symlinked into `~/.vscode/extensions` as `<publisher>.<name>-<version>`, also when no profile is selected, so VS Code loads it straight from the repository; a link of an older version of the same extension is removed, a real folder in the way is backed up into `Backups/Unix/SymbolicLinks`, and a manifest that is not JSON or lacks publisher, name or version is skipped with a warning. Local extensions are never installed from the Marketplace and never pruned, whether `extensions.txt` lists them or not, because an uninstall through the link would delete the repository copy. Each entry's folder under `root` (`VSCode/Profiles/<Name>`) is linked into the VS Code profile it targets: `settings.json`, `keybindings.json` (`keybindings.macos.json` wins on the Mac), `tasks.json` and `snippets/`; a real file it replaces is backed up into `Backups/Unix/SymbolicLinks`, a link already in place is left alone. A target other than `Default` that VS Code does not know is registered in `User/globalStorage/storage.json` (with jq, backed up first, refused while VS Code runs). The extensions `extensions.txt` lists that the profile lacks are installed with `code --install-extension` (`--do-not-sync` unless `settings-sync on`), a pinned one at its pin; extras stay unless `--prune` or `prune on`. A name outside the catalogue fails, an entry without a folder is skipped with a warning, a missing `code` skips the extensions. `--check` reports what a run would change. Bootstrap's opt-in VSCodeProfiles step. The local extensions are always linked into `~/.vscode/extensions`: the `-Destination` of the Windows Install-VSCodeLocalExtensions, a test seam there, has no Unix form.
- **Usage:** `Deploy-VSCodeProfiles [NAME[,NAME...]...] [--prune] [--check]` (the Windows-style `--name` is accepted and ignored)

## [Enable-ObsidianCli](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Enable-ObsidianCli)

- **Description:** Turns on the Obsidian command line interface for this machine by setting `"cli": true` in `~/Library/Application Support/obsidian/obsidian.json` (Linux: `~/.config/obsidian/obsidian.json`), the switch of Settings > General > Advanced > Command line interface. Refuses while Obsidian runs (it rewrites that file), backs the file up first, creates a missing file only with `--create-if-missing`; `--check` reports the state. `--settings-path FILE` (the Windows `-SettingsPath`) works on FILE instead of the default `obsidian.json`.
- **Usage:** `Enable-ObsidianCli [--create-if-missing] [--check] [--settings-path FILE]`

## [Export-VSCodeProfile](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Export-VSCodeProfile)

- **Description:** Captures the live VS Code profile a `vscode-profiles.conf` catalogue entry deploys onto back into its repository folder, as the Windows Export-VSCodeProfile does; run by hand, never by Bootstrap. Profile files that are links already are left alone (a link pointing elsewhere is reported), real files are copied in (keybindings into `keybindings.macos.json` when the folder carries one, an empty `snippets/` skipped), and `extensions.txt` is merged with `code --list-extensions`: comments, pins and entries still installed are kept, uninstalled ones dropped, new ones appended sorted. Nothing in VS Code changes; review with `git diff`
- **Usage:** `Export-VSCodeProfile NAME` (the Windows-style `--name NAME` works too)

## [Invoke-Browser](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Invoke-Browser)

- **Description:** Google search for QUERY in the default browser; without a query, the browser group menu. A leading Windows `-Query` is dropped (`b -Query how to x` searches `how to x`).
- **Usage:** `Invoke-Browser [QUERY...]`
- **Alias:** `b`

## [Open-Acrobat](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-Acrobat)

- **Description:** Opens every PDF of the named groups of `Unix/config/pdfs.conf` (AcrobatPdfGroups) in Adobe Acrobat (the `Acrobat` bundle id of `apps.conf`, found installed through Spotlight), or in the default PDF viewer when Acrobat is not installed. As on Windows, a call without any argument opens Acrobat itself without a menu (`Acrobat is already running!` when it runs), and `--pdf ''` (Windows' `-Pdf ""`) shows the menu: the groups, then up to 10 recently used PDFs (`Recent: NAME.pdf`, from Spotlight's last-used date of the last 90 days, newest first, so a PDF read in any viewer counts; Acrobat's own recent list cannot be read outside Acrobat); an empty Enter opens Acrobat itself. A GROUP may be a comma list (`MyProject,Learning`), and `--pdf` may stand before the groups. A group given as a menu number, or as a recent PDF's menu entry (`"Recent: NAME.pdf"`), is that entry of the menu, as `-Pdf` is on Windows; only then is Spotlight asked for the recent PDFs.
- **Usage:** `Open-Acrobat [GROUP...] [--pdf GROUP...]`

## [Open-Application](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-Application)

- **Description:** Launches an app of `Unix/config/apps.conf` (by token or bundle id, any case; the last `app` line of a token wins) unless AeroSpace lists a window of it; the generic launcher behind every `Open-<App>` workspace action without a dedicated command. At the prompt `Open-<App>` works too, as the Windows `Open-<App>` functions do (`Open-Slack` is `Open-Application Slack`): the shell rc defines an `Open-<TOKEN>` alias for every `apps.conf` token without a command of its own, so zsh completes them, and its command-not-found handler catches a token added since the shell started; there are no per-app files. `--list` prints every token. Without AeroSpace running there is no window check: the app is always opened, which brings a running instance forward rather than starting a second one. ARGUMENTs go to the app (`open -b BUNDLE --args ...`).
- **Usage:** `Open-Application TOKEN [ARGUMENT...]`, `Open-Application --list`, `Open-<TOKEN> [ARGUMENT...]` at the prompt

## [Open-Browser](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-Browser)

- **Description:** Opens each browser group of `Unix/config/browser-groups.conf` in its own new window (URLs as tabs); menu when no group is given, where an empty Enter opens a plain browser window. Each group waits for its window before the next one, and a group that is already open is skipped (`--force` opens it anyway), so rerunning a workspace does not duplicate windows: in Safari and the Chromium browsers (Chrome, Brave, Edge) a window whose tabs hold every URL of the group, background tabs included and a redirect deeper into the site counting (read through the browser scripting driver, the Test-BrowserGroupAlreadyOpen of Windows, which can only score window titles); in Firefox the window recorded when the group was opened. Firefox has no tab list and titles a window after its active tab only, so a group opened there by hand is not seen and a rerun opens it again: decided (2026-10-24) against a title guess, which could skip a group, while a duplicate window is the lesser harm. Safari (`launch=script` in `apps.conf`) gets a new window of the group's URLs through the same driver; it has no private window by script, so `--private` warns and opens a normal one. `--private` opens a private window only for a plain window or a search: with groups it warns (`Groups cannot be opened in private mode`) and opens them in a normal window, as on Windows (Tor Browser is private either way). Without Automation for the browser (System Settings > Privacy & Security > Automation) Safari cannot open a group and the others fall back to the recorded window. `--alongside` (an alongside workspace open) opens the groups as `--force` does, and with `--no-menu --instances N` opens N new windows instead of counting the ones already open. During a plain workspace open the windows of the alongside workspaces it leaves alone (the protected list Open-Workspace writes) are neither counted for `--instances` nor taken for an open group, as Windows skips its protected windows; a scripted browser's window counts as protected when one of its tab titles begins a protected window's title and none begins another window's, since its scripting dictionary shares no window id with AeroSpace. `--instances` only applies with `--no-menu`: with groups it is ignored, unlike Windows, where it padded the groups up to N windows (only the League of Legends workspace, not used on the Mac, relied on it). `--search QUERY` encodes the query as Windows' `UrlEncode` does (every byte but letters, digits and `-_.~` as `%XX`, a space as `+`), so `c++` searches for c++. `--override` (the Windows `-Override`) is `--force`. A comma list names several groups; a flag it does not know is an error, never a group. The menu is the group tree of the Windows menu, numbered `1`, `1.2`, `1.2.1`: nested groups and named URLs sit under their group, and an answer is an index path or a name (a group opens whole, a named URL alone). A group given as an index path of the menu tree (`Open-Browser 1.2`) is that entry, as `-Groups 1.2` is on Windows.
- **Usage:** `Open-Browser [GROUP[,GROUP...]...] [--browser TOKEN] [--private] [--force | --override] [--alongside] [--no-menu [--instances N]] [--search QUERY...]` (the Windows-style `--groups` is accepted and ignored)

## [Open-ClaudeDesktop](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-ClaudeDesktop)

- **Description:** Opens the Claude desktop app unless it already has a window: Open-Application for the `Claude` app of `apps.conf`, so ARGUMENTs go to the app and the window check needs AeroSpace. A leading `--help` prints its own header; `-v` and a later `--help` are taken by Open-Application and never reach the app.
- **Usage:** `Open-ClaudeDesktop [ARGUMENT...]`

## [Open-Docker](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-Docker)

- **Description:** Starts Docker Desktop without a window and returns at once, as on Windows: it does not wait for the daemon (Start-Containers, Docker-Cleanup and Run-Project wait for it themselves, up to `timeout start` of `docker.conf`), and a Docker Desktop that already runs is a warning (`Docker Desktop is already running!`) and is not started again; Docker Desktop counts as installed when `/Applications/Docker.app` exists, else when Spotlight knows an app of its bundle id `com.docker.docker` (a cask installed with `--appdir ~/Applications`), the check Run-Project, Start-Containers and Docker-Cleanup share; `--stop` stops the running containers and quits Docker Desktop, killing it after `timeout stop` seconds (60 without a line), as Kill-All's Docker step does. Any other argument is an error and starts nothing.
- **Usage:** `Open-Docker [--stop]`

## [Open-Obsidian](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-Obsidian)

- **Description:** Opens Obsidian for the vault and, when a workspace resolves, loads that saved Obsidian workspace through the official Obsidian CLI (`obsidian vault=<Vault> workspace:load name=<Name>`), as on Windows. The workspace comes from `--workspace` or a bare NAME (Windows' positional `-Workspace`); else, during a workspace open, from the Foundation workspace's own name when the vault has an Obsidian workspace of that name (`w Server` lands on Server): Open-Workspace hands it over in `FOUNDATION_CURRENT_WORKSPACE`, and `--current-workspace NAME` (Windows' `-CurrentWorkspace`) gives it by hand, beating the variable and suppressing the menu; else, on a bare terminal call without `--default`, from a menu of the saved workspaces (Enter skips); else from `default-workspace` of `Unix/config/obsidian.conf` on a cold start only. A cold start launches Obsidian detached (`open -g`) and polls the CLI for up to 10 s; with Obsidian running the workspace switches in place, and without a workspace a running Obsidian is left alone. Every CLI call is killed after 5 s (a probe after the time left of the wait), as Windows' Invoke-ObsidianCli, so a CLI that never hears back cannot stall a workspace open. A CLI refusal (switched off: Enable-ObsidianCli) is reported, never claimed as loaded; without the CLI at all the registration hint is printed and Obsidian still counts as opened (exit 0, nothing queued), as on Windows. No vault configured (neither `directory` nor `vault` in `obsidian.conf`, nor `--vault`) is an error. The menu is offered only when a prompt can be answered (the `FOUNDATION_TTY` terminal check every Foundation menu makes). A flag it does not know is an error, never taken for the workspace. `--vault NAME` opens that vault instead of the `vault` of `obsidian.conf`. During a workspace open the load is deferred, as Windows' `-Deferred`: Obsidian is started, the load is queued and the open goes on to its next action instead of waiting for Obsidian's CLI; Open-Workspace runs the queued load (`--load-only`: the CLI wait and the load, nothing else) just before its layout.
- **Usage:** `Open-Obsidian [NAME] [--workspace NAME] [--default] [--vault NAME] [--current-workspace NAME] [--load-only]`

## [Open-SecureBrowser](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-SecureBrowser)

- **Description:** Opens Tor Browser with the URLs, or a private window of the default browser when Tor Browser is not installed. Tor Browser counts as installed when `/Applications/Tor Browser.app` exists, else when Spotlight knows an app of its bundle id `org.torproject.torbrowser` (installed elsewhere, such as `~/Applications`); the `TorBrowser` app line gives the bundle id it is opened by. The fallback starts the default browser as Open-Browser does, from its `browser` line of `apps.conf`: its binary, LaunchServices (`launch=open`, the Chromium browsers) or the browser scripting driver (`launch=script`, Safari, which has no private window by script and opens a normal one with a warning). Unlike Windows it shows no IP, starts no RiseupVPN and runs no privacy check: Invoke-TorRequest, Invoke-PrivacyRequest and Test-PrivacyStatus are not ported, because neither Tor Browser nor RiseupVPN is installed on the Mac (decided 2026-10-18). A flag it does not know is an error, never opened as a URL.
- **Usage:** `Open-SecureBrowser [URL...]`

## [Open-Terminal](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-Terminal)

- **Description:** Opens WezTerm tabs in a new window (or this one with `--in-same-shell`, by WezTerm window id, so they never land in another WezTerm window), one per COMMAND, with optional titles and directories; a tab without `--cwd` starts on the Desktop (the home folder when there is none), as Windows Terminal's `startingDirectory`. Outside a WezTerm pane `--in-same-shell` opens a new window: a `WEZTERM_PANE` inherited by an app started from WezTerm does not count. A flag it does not know is an error, never typed into a tab (a command with flags goes in quotes: `t 'ls -la'`). `--window-id ID` chooses the window as Windows' `-WindowId`: `0` is the window this shell runs in (`--in-same-shell`), a number the WezTerm window with that id (`wezterm cli list`), and any other value names a window: the first call opens a new window and remembers it under that name (`$FOUNDATION_STATE_DIR/terminal-windows`), later calls with the name join it while it is open, and a closed one is replaced by a new window. The Windows arrays split: `-TabTitles A,B` and `-TabTitles "A", "B"` name two tabs, `-Command "a", "b"` runs two; a comma inside one quoted command stays part of it.
- **Usage:** `Open-Terminal [COMMAND...] [--title T]... [--cwd DIR]... [--in-same-shell] [--window-id ID]` (the Windows-style `--tab-titles A,B`, `--command A, B`, `--working-directory` and `--administrator` work too)
- **Alias:** `t`

## [Open-VSCode](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-VSCode)

- **Description:** Opens VS Code, one new window per folder of `Unix/config/vscode-folders.conf`; a folder whose name is already a whole segment of a VS Code window title (between ` - ` or VS Code's macOS em-dash separator, case-insensitive) is not opened twice, so `MyApp` still opens while only `myapp-ui` is open. The titles come from AeroSpace, or from System Events when AeroSpace does not answer, so the check holds without the tiling manager. Without a folder the folder menu is shown; an empty Enter opens VS Code itself unless it already runs (a VS Code window, or the app running without one), and `--default` does the same without the menu, as the Windows `-Default`. A FOLDER may also be given with `--folder` (Windows' `-Folder`); when several lines have the name the last one gives the folder, so a `.local` overlay line overrides the base line, and the menu lists each name once. During a workspace open with a VS Code workspace override it opens that `.code-workspace` through Open-VSCodeWorkspace instead. A `code` launch that fails is reported and makes the exit 1; the other folders still open. A comma list names several folders; a flag it does not know is an error and nothing opens. A folder given as a number is that entry of the menu, as `-Folder 2` is on Windows.
- **Usage:** `Open-VSCode [FOLDER[,FOLDER...]...] [--folder FOLDER[,FOLDER...]] [--default]`

## [Open-VSCodeWorkspace](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Application/bin/Open-VSCodeWorkspace)

- **Description:** Opens VS Code multi-root workspaces by file base name from the `directory` of `Unix/config/vscode-workspaces.conf` (`VSCode/Workspaces`: `MyProject` => `MyProject.code-workspace`), or a menu of them; a workspace is skipped when `NAME (Workspace)` is already a whole segment of a VS Code window title (a folder window `NAME` does not count), the titles read from AeroSpace or, when it does not answer, from System Events. A `code` launch that fails is reported and makes the exit 1; the other names still open. Open-VSCode reroutes here during `w` when the workspace has a `default` line or `--vscode-workspace` is given. A comma list names several workspaces; a flag it does not know is an error and nothing opens. A workspace given as a number is that entry of the menu, as `-VSCodeWorkspace 2` is on Windows.
- **Usage:** `Open-VSCodeWorkspace [NAME[,NAME...]...]` (the Windows-style `--vscode-workspace` is accepted and ignored)
