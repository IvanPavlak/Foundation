# AI

Deploys the AI skills, mods, rules, prompts and agents into the AI apps of the machine, installs the Claude Code plugin marketplaces, adds the MCP servers to Claude Code and Codex, lists the artifacts the repository carries and vendors them from upstream.

Manifest: [`Unix/modules/AI/module.conf`](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/AI/module.conf). One entry per command, alphabetical; the bullet block right under each heading is the parsed part.

The mechanism (the artifact layout, the sources read, the harness catalogue and the folders each
app reads, the rules and the hooks) is on [AI on a Mac](../ai.md); the two config files are on
[Configuration](../configuration.md#ai-artifactsconf-and-ai-harnessesconf). `Deploy-AiArtifacts`,
`Deploy-AiMarketplaces` and `Deploy-AiMcpServers` call the CLI that `FOUNDATION_CLAUDE_CLI` names (default `claude`); the
test suites set a name that never exists, or their stand-in, so a suite never reaches the real CLI.

## [Deploy-AiArtifacts](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/AI/bin/Deploy-AiArtifacts)

- **Description:** Links the AI skills, mods, rules, prompts and agents of the artifacts root (`root` of `Unix/config/ai-artifacts.conf`, default `AI`, laid out `<Kind>/<source>/<item>`) into the harnesses of the `deploy` line of `ai-artifacts.conf`, each a section of `ai-harnesses.conf` whose lines are its destinations (`KIND PLACEMENT FILES [+HOOK...] PATH`). The sources read are `own` first, then `foundation`, `example` and the vendored sources in name order; the first wins an item name two carry, with a warning, and `exclude KIND/NAME` or `KIND/SOURCE/NAME` lines leave items out. An `each` destination gets one link per item (the folder, or the first file of the destination's list the item has, named `<item>` plus its extension), `copy` the same as copies (one that differs is replaced), `file` one link to the item of the `use KIND NAME` line. A destination two harnesses name is filled once; one no item goes to is never created. A folder destination that links into the repository becomes a real folder, one that links elsewhere or a file in its place is skipped; a real item where a link or copy goes is first copied into `Backups/Unix/SymbolicLinks/AiArtifacts.<kind>.<item>` (a `file` destination adds `.<file>`), and when that copy fails it is skipped and the run fails; only dangling links into the artifacts root are pruned. Hooks: `+claude-plugin-dirs` sets `env.CLAUDE_CODE_PLUGIN_DIRS` of `~/.claude/settings.json` to the destination's links, `:`-joined, then every entry added by hand (python3 edits the JSON, every other setting kept; an unparseable file is left untouched and fails the run), and runs `claude plugin validate` on each (a missing or rejecting CLI only warns); `+managed-settings` makes the link through sudo. No `deploy` line is a warning, not a failure. `--kind` deploys only those kinds; `--check` reports what a run would change and changes nothing
- **Usage:** `Deploy-AiArtifacts [--kind KIND...] [--check]`; Windows-style `-WhatIf` is `--check`

## [Deploy-AiMarketplaces](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/AI/bin/Deploy-AiMarketplaces)

- **Description:** Registers the marketplaces of `Unix/config/ai-marketplaces.conf` under `extraKnownMarketplaces` of `~/.claude/settings.json`, writes each section's `env NAME VALUE` lines into the `env` block (the variables its plugins need Claude Code to read from its settings, such as `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS 1` on Claude Code 2.1.286; every other variable kept, a later section wins the same name), sets each plugin's `option` lines as `pluginConfigs.<plugin>@<marketplace>.options` (replacing that key whole) and each `config PLUGIN CHILD VALUE` line as one more child key of that entry, every other setting kept; a `[plugin:NAME]` section writes its `option KEY VALUE` and `config CHILD VALUE` lines beneath `pluginConfigs.<NAME>`, for a plugin no marketplace installs (a folder-loaded mod). Then, with the `claude` CLI on PATH, it adds every marketplace and installs every plugin the CLI does not list yet (a failed add or install fails the run, the rest is still tried); a missing CLI only warns, and so does one resolved under `/mnt/` (inside WSL, the Windows CLI through interop, which would install into the Windows profile). A folder in `env.CLAUDE_CODE_PLUGIN_DIRS` holding a plugin installed here is reported, never removed: the folder copy would load a second time and ignore the options under `pluginConfigs.<plugin>@<marketplace>`. Marketplaces are not an artifact kind: the plugins install through Claude Code's own CLI. `--check` reports the current state and changes nothing
- **Usage:** `Deploy-AiMarketplaces [--check]`; Windows-style `-WhatIf` is `--check`

## [Deploy-AiMcpServers](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/AI/bin/Deploy-AiMcpServers)

- **Description:** Adds the MCP servers of `Unix/config/ai-mcp-servers.conf` (one `[section]` per server: a `url` with optional `transport sse`, `header NAME VALUE` and `bearer-token-env NAME` lines, or a `command` with `arg` and `env NAME VALUE` lines; a `machine TYPE...` line or an `@TYPE` prefix scopes it) to the apps of the last `deploy` line for this machine type, `claude-code` and `codex`. Claude Code: with the `claude` CLI on PATH, a server the `mcpServers` block of `~/.claude.json` (`$CLAUDE_CONFIG_DIR/.claude.json` when set) does not carry is added with `claude mcp add --scope user`, one it carries with another definition is removed with `claude mcp remove --scope user` and added again, and one it carries as configured is left alone; the file is only read, and python3 runs the CLI with each argument exactly as configured. Codex: each server's `[mcp_servers.<name>]` table is written to `~/.codex/config.toml` (`$CODEX_HOME/config.toml` when set), replacing that table and its subtables in place or appending it, every other line, comments and the file's line endings kept; an `sse` server is skipped there with a warning, since Codex reads stdio and streamable HTTP servers only. `bearer-token-env NAME` becomes an `Authorization: Bearer ${NAME}` header for Claude Code and `bearer_token_env_var` for Codex, so no token is written. A missing CLI only warns, and so does one resolved under `/mnt/` (inside WSL, the Windows CLI through interop); an unparseable `~/.claude.json`, an invalid server or a failed CLI call fails the run, the rest is still deployed. Servers are added and updated, never removed. MCP servers are not an artifact kind: each app keeps them in its own configuration file. `--check` reports what a run would add or update and changes nothing
- **Usage:** `Deploy-AiMcpServers [--check]`; Windows-style `-WhatIf` is `--check`

## [List-AiArtifacts](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/AI/bin/List-AiArtifacts)

- **Description:** Lists the AI artifacts the repository carries, as `Deploy-AiArtifacts` reads them (the sources read, own first, the first source winning a name two carry, the `exclude` lines applied), grouped by kind and source, with the description of each item's frontmatter (a mod's `plugin.json`). `--kind` picks kinds, `--source` sources and `--name` item names by wildcard pattern (case-insensitive) or by number (the position in the sorted list); a bare `--source` or `--name` opens a menu, and a filter that matches nothing warns. `--list-discrepancies` holds the deploy plan of the harnesses turned on against the disk: an item not linked (or not copied, or a copy that differs), an entry that shadows one with a real file or points elsewhere, a missing destination folder, a dangling link into the artifacts root, an item name two sources carry, a configuration warning; exits 1 when there are any. `--quiet` prints names only (with `--list-discrepancies`, no all-clear banner)
- **Usage:** `List-AiArtifacts [--kind KIND...] [--source [NAME|NUMBER...]] [--name [PATTERN|NUMBER...]] [--list-discrepancies] [--quiet]`

## [Update-AiArtifacts](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/AI/bin/Update-AiArtifacts)

- **Description:** Vendors AI artifacts from the sources of `Unix/config/ai-artifacts.conf` (each `[section]`: `repository`, `ref`, one `KIND PATH...` line per kind it feeds, default `skills skills`, `exclude`, `skip`) into `<root>/<Kind>/<source>/`, pinned: resolves `ref` to an exact commit through the GitHub API, downloads that commit's archive, and per kind copies the items under its folders - skills (a folder holding `SKILL.md`, the category level dropped), mods (a folder holding `.claude-plugin/plugin.json`, named by its `name`), rules, prompts and agents (every subfolder; a top-level `NAME.md` becomes item `NAME` holding it as `RULES.md`, `PROMPT.md` or `AGENT.md`) - without the `skip` entries (default `.git .github tests design docs`), and writes an `UPSTREAM.md` per kind folder and the upstream license, its re-run line naming `Update-AiArtifacts SOURCE`. Removes only the items the previous manifest lists, so hand-made folders survive; a source whose kind finds no item, a failed download or an empty archive leaves the vendored copy untouched and fails the run. `--check` compares each pinned commit with the upstream head and changes nothing. Private repositories work with a GitHub token (`GITHUB_TOKEN`, else `GH_TOKEN`, else `gh auth token` from a signed-in GitHub CLI): both requests authenticate and the archive comes from the API's tarball endpoint; the token goes only to `api.github.com` and is never logged. Needs curl and python3
- **Usage:** `Update-AiArtifacts [SOURCE...] [--check]` (the Windows-style `--source` is accepted and ignored)
