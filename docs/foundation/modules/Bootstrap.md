# Bootstrap

Provisions a Mac: the Bootstrap runner and its steps - the first-run identity and paths, dotfiles, the Firefox profile, system defaults, power settings, Dock pins, login items, dotnet-ef, Conda environments, the NuGet config, the npm registry token and where Docker Desktop installs its tools.

Manifest: [`Unix/modules/Bootstrap/module.conf`](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/module.conf). One entry per command, alphabetical; the bullet block right under each heading is the parsed part.

## [Bootstrap](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Bootstrap)

- **Description:** Provisions this Mac in a fixed order of 40 idempotent steps (InitializeConfiguration, RenameMachine, Homebrew, HomebrewBash, Packages, Dotfiles, GitIdentity, MachineType, Permissions, RepositoryUpdate, ObsidianSettings, SystemDefaults, SpecialFolders, Power, Spotlight, Firewall, SoftwareUpdate, Rosetta, SystemTheme, Locale, DisplayLanguage, KeyboardLayouts, DockPins, LoginItems, FirefoxProfile, VSCodeProfiles, AiArtifacts, AiMarketplaces, AiMcpServers, ObsidianCli, DotnetEf, DotnetSdks, CondaEnvironments, NuGetConfig, NpmConfig, DockerDesktop, UpgradeAll, PersonalSteps, AeroSpace, Logout), each a Foundation command or a short inline step. A step runs per its built-in default, then the `step NAME on|off` lines of `Unix/config/bootstrap.conf` and `bootstrap.local.conf`, then `--include`, then `--skip`, which wins with a warning; `--only` runs just the named steps; InitializeConfiguration, RenameMachine and Permissions run only with `--with-initial-setup` (or when `--only` names them). After InitializeConfiguration the remaining steps are resolved again, so the `@TYPE step` lines of the machine type it recorded govern the rest of the run, as on Windows. The administrator password is asked once, and only when an enabled step needs root (Packages counts, for pkg installers), before the first step or, when InitializeConfiguration turned such a step on, right after it; a refused password skips the steps that cannot run without it, and the exit status is then 1 even when no step failed. The Dotfiles step copies every real file or folder a chezmoi link would replace into `Backups/Unix/SymbolicLinks/` before `chezmoi apply`, as `bootstrap.sh` does, and applies nothing when a copy fails; it is skipped when chezmoi runs Bootstrap (`CHEZMOI=1`). GitIdentity fills an unset global `user.name` / `user.email`; run alone (`--only GitIdentity`, the Install-Git analog) it also replaces one that differs from `git.local.conf`. RepositoryUpdate takes group names only: a `repository-scope` name that is no `repositories.conf` group is reported, nothing is updated and the step fails. After the language steps, when any of them ran, Display-SystemLanguageSettings reads back what they applied. The Homebrew step's dry run names the installer without downloading it. The ObsidianSettings step links the Obsidian vault's `.obsidian` to the `settings` folder of `obsidian.conf` (the Obsidian link of the Windows SymbolicLinks), backing up a real folder first; it does nothing without a `settings` line and skips a vault that is not cloned yet with a warning. A failed step does not stop the run: the summary names it and the exit status is 1. Like the Windows Start-Logging / Stop-Logging, a run keeps a transcript of everything it prints, the tools' own output included, in `~/Desktop/BootstrapLog_<yyyy-MM-dd_HH-mm-ss>.log` (colour codes left out, outside the session-log retention) and ends with `Log file location =>` and `Total duration =>`; a dry run keeps no transcript. `--list` prints every step with its default and its state; `--dry-run` passes each command its own dry run (`--dry-run` or `--check`), prints the inline commands, never asks for the password and changes nothing. See [Bootstrap a Mac](../bootstrap.md)
- **Usage:** `Bootstrap [--list] [--dry-run] [--with-initial-setup] [--skip STEP...] [--include STEP...] [--only STEP...]`

## [Configure-DockerDesktop](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Configure-DockerDesktop)

- **Description:** Sets where Docker Desktop installs its command-line tools, from the `cli-install system|user` line of `Unix/config/docker.conf`: system links them into `/usr/local/bin` (Docker Desktop asks for the administrator password once), user into `~/.docker/bin`, which Docker Desktop then puts on PATH by writing a block into `~/.zprofile` and `~/.bash_profile` at every start (the latter a link into the repository). Without a line, or with another value, nothing changes. The mode is `DockerBinInstallPath` of Docker Desktop's `settings-store.json` (`~/Library/Group Containers/group.com.docker/`), read and written with `plutil`; a Docker Desktop that never ran has no such file yet, which is a warning (start it once, then run this again), and a mode already set changes nothing. Otherwise a running Docker Desktop is stopped first (its containers too, as `Open-Docker --stop`; one still running after `timeout stop` is left unchanged and the command fails), the file is copied into `Backups/Unix/System/DockerDesktop/`, the key is written and read back, and Docker Desktop is started again in the background when it was running. `--dry-run` says what would change and stops or writes nothing; `--backup-root DIR` puts the backup under `DIR/System/DockerDesktop/`. Bootstrap's DockerDesktop step (off by default). Foundation only: WinuX has no counterpart.
- **Usage:** `Configure-DockerDesktop [--dry-run] [--backup-root DIR]`

## [Configure-NpmConfig](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Configure-NpmConfig)

- **Description:** Writes a GitHub personal access token into the user npmrc (`npmrc` of `Unix/config/npm.conf`, default `~/.npmrc`; a relative path starts at the repository root) for every `registry URL [SCOPE]` line of `npm.conf` (the base ships `https://npm.pkg.github.com/`, GitHub Packages; the last line of a URL wins): the `//HOST/PATH/:_authToken=TOKEN` line and, with a SCOPE, the `SCOPE:registry=URL` line, so `npm install` of a private scoped package authenticates. A registry whose token line has a value and whose scope line matches is left alone; when every registry is configured nothing is asked or written, otherwise, or with `--override`, the token (read:packages; the one Configure-NuGetConfig asks for works) is asked once on the terminal (hidden; an empty answer, or one with whitespace in it, asked again: GitHub tokens have none) and written for every registry that needs it. Every other npmrc line keeps its place: a stale line is replaced where it stands, a duplicate dropped, a missing line appended. The token is never passed to another program, logged or printed, and the npmrc is made readable by its owner only. An existing file is first copied into `Backups/Unix/System/NpmConfig/` with every credential value (`_authToken`, `_auth`, `_password`) replaced by `<redacted>`, so the copy keeps the other settings but no token, and left alone when that fails. Without registry lines it does nothing. `--dry-run` names the registries that would be written without asking. Exit status 1 without a terminal, without an answer, or when the backup or the write failed. `--backup-root DIR` (the Windows `-BackupRoot`) puts the backup under `DIR/System/NpmConfig/` instead of `Backups/Unix`.
- **Usage:** `Configure-NpmConfig [--override] [--dry-run] [--backup-root DIR]`

## [Configure-NuGetConfig](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Configure-NuGetConfig)

- **Description:** Writes the NuGet config template (`nuget-template` of `Unix/config/dotnet.conf`, default `NuGet/nuget.config`) to `nuget-config` (default `~/.nuget/NuGet/NuGet.Config`; a relative path in either starts at the repository root, not the current folder) with a GitHub username and personal access token filled in for its `[Username]` and `[Token]` placeholders, both asked for on the terminal (the token hidden, empty answers asked again). An existing config whose package sources (key and URL) match the template's is left alone; a missing, changed or extra source, or `--override`, rewrites it. An existing file is first copied into `Backups/Unix/System/NuGetConfig/` with every `ClearTextPassword` and `Password` value replaced by `REDACTED`, so the copy keeps the sources but no token, and left alone when that fails. A token with whitespace in it is asked again: GitHub tokens have none, so it is something else pasted by mistake (a command pasted with the token). NuGet on macOS keeps the token in clear text, so the file is made readable by its owner only. `--dry-run` compares and prints what would be written without asking. Exit status 1 without a terminal, without an answer or when the write failed. `--backup-root DIR` (the Windows `-BackupRoot`) puts the backup under `DIR/System/NuGetConfig/` instead of `Backups/Unix`.
- **Usage:** `Configure-NuGetConfig [--override] [--dry-run] [--backup-root DIR]`

## [Deploy-FirefoxProfile](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Deploy-FirefoxProfile)

- **Description:** Links `Firefox/user.js` (Betterfox) into the default Firefox profile read from `profiles.ini` (`--all`: every profile); an existing real `user.js` is first copied into `Backups/Unix/SymbolicLinks/` and not replaced when that fails; Firefox applies it on its next start. `--check` reports each profile and changes nothing; an unknown argument is an error. macOS protects Firefox's data folder, so the first run may ask to let the terminal access data from other apps.
- **Usage:** `Deploy-FirefoxProfile [--all] [--check]`

## [Initialize-Configuration](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Initialize-Configuration)

- **Description:** Writes what makes a generic clone this user's Mac into the `.local` overlays, as the Windows Initialize-Configuration writes `Configuration.local.psd1`: the git identity (`name` / `email` in `git.local.conf`, set as the global identity by the GitIdentity step), this Mac's `host NAME TYPE` line and its machine type's `@TYPE dev-root PATH` line (the dev root configured paths name as `$DEV`) in `machines.local.conf`. Each value comes from its flag, else `FOUNDATION_GIT_NAME` / `FOUNDATION_GIT_EMAIL` / `FOUNDATION_DEV_ROOT`, else a prompt with the default (Enter keeps it), else - without a terminal - the default, so a scripted run never waits. Defaults: the current name, the machine type chezmoi asked on the first run (else the detected one), the folder holding the clone as the dev root; the identity has none. Only what is not set yet is asked and written (an identity in `git.local.conf` or the global git config, a host line for this name, a dev root for this type); `--force` asks and writes everything again, replacing those lines. `--machine-name` or `--machine-type` replaces the host line and `--dev-root` (or `FOUNDATION_DEV_ROOT`) the dev-root line even without `--force`, while `--git-name` and `--git-email` are ignored when an identity is already set, unless `--force`. An overlay is backed up into `Backups/Unix/Config/` before it changes; a missing one is created. The first step of `Bootstrap --with-initial-setup`; RenameMachine then applies a new name. `--owner NAME` (the Windows `-Owner`) is the default of the git name prompt, and the git name of a run without a terminal, while no identity is set.
- **Usage:** `Initialize-Configuration [--git-name NAME] [--git-email ADDRESS] [--owner NAME] [--machine-name NAME] [--machine-type TYPE] [--dev-root PATH] [--force] [--dry-run] [-v]` (the Windows-style `--dev-path` is `--dev-root` and `--what-if` is `--dry-run`)

## [Install-CondaEnvironments](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Install-CondaEnvironments)

- **Description:** Creates the Conda environments of `Unix/config/conda-environments.conf`: every `env NAME` line creates NAME from NAME.yml in the `directory` of the file (default `Conda/Environments/macOS`, relative to the repository root), and without env lines every .yml file there is created. The environment is named after its file; one that `conda env list` already shows is left alone. `update-base on` first runs `conda update -n base -c defaults conda` (off by default). conda 26 refuses to create any environment, a conda-forge one included, until the Anaconda Terms of Service of its defaults channels are accepted; a refusal prints the `conda tos accept` command to run once. Without conda on PATH, or without the folder (a clone that does not ship one), it warns and does nothing. `--list` shows each file and whether its environment exists, `--dry-run` prints the conda commands; neither changes anything. Exit status 1 when an environment could not be created
- **Usage:** `Install-CondaEnvironments [--list] [--dry-run]`
- **Alias:** `Create-CondaEnvironments` (the Windows command name)

## [Install-DotnetEf](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Install-DotnetEf)

- **Description:** Installs the EF Core CLI (`dotnet ef`) as a global .NET tool, at the `ef-version` of `Unix/config/dotnet.conf` (`8.0.11`, `8.*`, or empty or missing for the latest). Without the .NET SDK it does nothing; a dotnet-ef that `dotnet tool list --global` already shows is left alone. `--update` installs the latest version instead, `--dry-run` prints the dotnet command and changes nothing. The tool lands in `~/.dotnet/tools`. Exit status 1 when dotnet failed
- **Usage:** `Install-DotnetEf [--update] [--dry-run]`

## [Install-DotnetSdks](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Install-DotnetSdks)

- **Description:** Installs each `sdk-channel CHANNEL` of `Unix/config/dotnet.conf` (`6.0`, ...) that `dotnet --list-sdks` does not list yet with Microsoft's `dotnet-install.sh --channel CHANNEL`, into the dotnet root of the SDKs the Homebrew casks installed (the real folder of the `dotnet` on PATH, `/usr/local/share/dotnet`), with sudo because that root belongs to root, so it is listed beside them and `global.json` can select it. For the channels no cask ships: the `dotnet@6` formula is disabled since 2025-11-12 and no cask carries .NET 6 (the .NET 6 SDK of the Windows app list). Without lines it does nothing; without the .NET SDK it warns and does nothing; `--dry-run` prints what it would install. The Bootstrap step DotnetSdks runs it (off by default: it needs the password). Exit status 1 when a channel failed
- **Usage:** `Install-DotnetSdks [--dry-run]`

## [Set-DockPins](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Set-DockPins)

- **Description:** Pins the apps and folders of `Unix/config/dock.conf` to the Dock with `dockutil`: `pin PATH` lines are apps in order, `spacer` adds a gap, `folder PATH [OPTION...]` a folder on the right with dockutil options (`--view fan --display stack`). With `clear on` the Dock is made to hold exactly that list (left alone when it already does, otherwise emptied and refilled in order; a list with a spacer is refilled on every run, since spacers cannot be compared); with `clear off`, or without a `clear` line, only missing pins are added. Before the Dock is emptied its preferences (`com.apple.dock`) are backed up into `Backups/Unix/System/DockLayout/` (restore: `defaults import com.apple.dock <backup>/com.apple.dock.plist; killall Dock`); when the backup fails the Dock is left as it is and the exit status is 1. Missing apps or folders are skipped with a warning, `@TYPE` lines apply on one machine type, and the Dock restarts once, only when something changed. Without `dockutil` it warns and changes nothing. `--list` shows the Dock next to `dock.conf`, `--dry-run` prints the dockutil commands; neither changes anything. Exit status 1 when a dockutil call failed
- **Usage:** `Set-DockPins [--list] [--dry-run]`

## [Set-LoginItems](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Set-LoginItems)

- **Description:** Makes the apps of `Unix/config/login-items.conf` start at login through System Events: an `item PATH [hidden]` whose app is not a login item yet (compared by name, case-insensitively) is added, `hidden` starts it without a window; an app that is not installed is skipped with a warning. Items are only added, never removed. The first run asks to let the terminal control System Events; when that is refused it stops with the pane to open. `--list` shows the login items next to the file, `--dry-run` prints what would be added; neither changes anything. Exit status 1 when an item could not be added
- **Usage:** `Set-LoginItems [--list] [--dry-run]`

## [Set-PowerSettings](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Set-PowerSettings)

- **Description:** Applies the sleep and power settings of `Unix/config/power.conf` with `pmset`: `[AC]` on the charger (`-c`), `[Battery]` on battery (`-b`, skipped on a Mac without a battery), `[All]` on every source (`-a`), one `sudo pmset` call per section with only the keys whose value differs, so the administrator password is asked for only when something changes. A key `pmset -g cap` does not list is skipped with a warning; an `@TYPE` line applies on one machine type only. `--list` shows each key with its current and configured value, `--dry-run` prints the pmset commands; neither changes anything. Exit status 1 when a pmset call failed
- **Usage:** `Set-PowerSettings [--list] [--dry-run]`

## [Set-SystemDefaults](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Bootstrap/bin/Set-SystemDefaults)

- **Description:** Applies the macOS settings of `Unix/config/system-defaults.conf`, one group per section in file order (Dock, Finder, Keyboard, Screenshots, HotCorners, Theme, ...): `defaults`, `currenthost` and `delete` lines write the preference domains (TYPE `-bool`/`-boolean`, `-int`/`-integer`, `-float`, `-string`, `-date`, `-data`, `-array`, `-array-add`, `-dict`, `-dict-add`; a key with spaces in double quotes), `mkdir` creates a folder a setting points at, `command` runs another Foundation command (the base Theme group runs `Set-SystemTheme --auto --skip SetWallpaper`; the wallpaper follows in the bootstrap's SystemTheme step), `restart` lines restart each named process once at the end, `note` lines are printed last. GROUP runs only those groups, `--skip` leaves groups out (comma lists, any case); an `@TYPE` line applies on one machine type only, and an empty section in `system-defaults.local.conf` turns a group off. `--list` and `--dry-run` print every command and change nothing. Runs as the user, no sudo; the power settings are `Set-PowerSettings` (the removed `--with-sudo` is still accepted and only warns so). Exit status 1 when a write failed. The Windows-style `-WhatIf` is `--dry-run`; any other flag it does not know is an error before anything is applied.
- **Usage:** `Set-SystemDefaults [GROUP...] [--skip GROUP...] [--list] [--dry-run]`
