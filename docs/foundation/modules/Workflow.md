# Workflow

Workspaces, projects, their terminals, Docker containers and EF Core migrations.

Manifest: [`Unix/modules/Workflow/module.conf`](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/module.conf). One entry per command, alphabetical; the bullet block right under each heading is the parsed part.

## [Close-Project](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Close-Project)

- **Description:** Closes what Open-Project opened for a project and leaves workspace apps running: the VS Code windows of its folders (the folder name a whole segment of the window title, so closing `MyApp` leaves a `myapp-ui` window open), its browser tabs whose title or URL names the project (or that show Swagger UI when the project has a Swagger entry, and the failed-load page, `problem-page-title` of `window.conf`, when that entry's URL is on this machine: host `localhost` or `127.0.0.1`, as on Windows) and its terminal tabs (Close-ProjectTerminals, never the tab it runs in). In Safari and the Chromium browsers (Chrome, Brave, Edge) just those tabs close, in every one that runs (the Close-BrowserTabsByPattern of Windows, through the browser scripting driver); Firefox cannot be scripted, so a window whose title (its active tab) matches closes as a whole, as does a scriptable browser's window while the terminal may not control it (System Settings > Privacy & Security > Automation). Focus then returns to the window the command was typed in, or to this shell's terminal window when that one was closed. A comma list names several projects; a flag it does not know is an error and nothing is closed. A project given as a number is that entry of the menu, as `-Project 2` is on Windows.
- **Usage:** `Close-Project [PROJECT[,PROJECT...]...]` (the Windows-style `--project` is accepted and ignored)

## [Close-ProjectTerminals](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Close-ProjectTerminals)

- **Description:** Closes the WezTerm tabs titled `<Project>.*`, keeping the whole tab it runs in (split panes included). A `WEZTERM_PANE` inherited by a process outside that pane (an app started from WezTerm, such as VS Code) does not count as the tab it runs in. A flag it does not know is an error, never taken for a project.
- **Usage:** `Close-ProjectTerminals PROJECT[,PROJECT...]...` (the Windows-style `--project-name` and `--project` are accepted and ignored)

## [Close-Workspace](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Close-Workspace)

- **Description:** Closes everything a workspace opened, and nothing else. Ownership is the record Open-Workspace wrote (new windows and panes plus the windows its layout adopted). Unlike Windows, it does not also close the other windows standing on the workspace's desktops: the recorded window ids are exact, while AeroSpace desktops are numbered, shared and owned by no workspace, so "the workspace's desktops" would be a guess (a deliberate difference); a recorded window is found by its id, else re-resolved as by the Windows Resolve-TrackedWorkspaceWindow (the same app when it has exactly one window left - an app that recreated its window - else the same app and exact title - an app that restarted; never a terminal window, never a window another open workspace owns by id); an app whose every window is owned is asked to quit (Cmd+Q), otherwise only owned windows close. Nothing is force-killed, as on Windows: an app still running 5 s after the request is reported ("did not quit - leaving it alone (it may be waiting on unsaved work)") and left running, so a save sheet keeps its work. The terminal is closed pane by pane, never quit; the pane `cw` runs in, when the workspace owns it, closes last, after the summary, and either way focus returns to this terminal (Focus-TerminalTab), as on Windows. Without a name the menu of open workspaces is shown (empty Enter cancels). A workspace open twice (plain, then `--alongside`) has a record per instance, as on Windows: the menu offers each, labelled `Name (plain, desktop 1)` / `Name (alongside, desktop 6)` (`instance N` when none of its windows is open), a bare name closes every instance and a full label only that one. `--all` closes every instance of every workspace. `--dry-run` (the Windows `-WhatIf`) lists the apps it would quit, the windows it would close and the tabs it would close, and changes nothing, the record included. A comma list names several workspaces; a flag it does not know is an error and nothing is closed. A workspace given as a number is that entry of the menu, as `-Workspace 1` is on Windows.
- **Usage:** `Close-Workspace [WORKSPACE[,WORKSPACE...]...|LABEL] [--all] [--dry-run]` (the Windows-style `--workspace` is accepted and ignored)
- **Alias:** `cw`

## [Docker-Cleanup](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Docker-Cleanup)

- **Description:** Menu of the `cleanup` actions of `Unix/config/docker.conf` plus All, which runs every configured action (the base file ships stop all containers, delete all containers, images and volumes, prune networks and the build cache), several at once. Selected actions run in configuration order. Before anything runs, each prints its description and what its `cleanup-preview` lists; an action with nothing to do is skipped, and when any remaining action has a `:: CONFIRMATION` one red confirmation (Enter means no) covers them all; actions without one run unasked. A failing action is reported and the others still run. When the daemon is down, `cleanup-start` asks to start Docker (Enter means yes), starts it without asking, or warns and stops. ACTION arguments (`--action` before them is the Windows `-Action`) are checked before Docker is touched: an unknown action or flag starts nothing. Without a terminal the start question counts as no: Docker is not started and nothing runs.
- **Usage:** `Docker-Cleanup [ACTION...|All]`

## [DockerWizard](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/DockerWizard)

- **Description:** The Windows DockerWizard: starts Docker Desktop with no window and waits for the daemon (`timeout start` of `Unix/config/docker.conf`, 180 s without a line), then brings up any Compose file with `docker compose up -d`: `--compose-file-path FILE`, or `--compose-project-path DIR` for the first of `compose.yaml`, `compose.yml`, `docker-compose.yaml` and `docker-compose.yml` in DIR (the order `docker compose` uses; a file path wins). `up -d` runs even when the stack is up, reconciling a half-stopped one. `--stop` stops the running containers and quits Docker Desktop, as `Open-Docker --stop`, ignoring the compose flags. Exit status 1 when something asked for did not happen (the daemon, a missing compose file, a failed `up -d`); `--pass-thru` is accepted and changes nothing, the exit status being the status. A flag it does not know is an error and Docker is not touched
- **Usage:** `DockerWizard [--compose-file-path FILE | --compose-project-path DIR] [--stop] [--pass-thru]`

## [EfCoreMigrationWizard](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/EfCoreMigrationWizard)

- **Description:** Interactive, menu-driven Entity Framework Core migration manager for a .NET solution. Finds the nearest `.sln`/`.slnx`, discovers the migration projects (dedicated `*Migration(s)*` projects, or Domain projects with a `Migrations` folder), marks the active provider from appsettings (`DatabaseConfiguration.UseNpgSql`/`UseOracle`/`UseSqlServer`), resolves the startup project (Api/Web/WebApi/Startup with `Microsoft.EntityFrameworkCore.Design`) and the DbContext (snapshot, sources, then `dotnet ef dbcontext list`), and offers add, redo last, remove last (reverting the database first), squash all into `initial-migration` (confirmed), and sync a migration to the other database projects
- **Usage:** `EfCoreMigrationWizard`, `efm`
- **Alias:** `efm`

## [Focus-TerminalTab](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Focus-TerminalTab)

- **Description:** Brings the WezTerm window this shell runs in to the front (activates the pane, focuses the window through AeroSpace). The window is the one whose title WezTerm built from the pane (`[i/n] TITLE`, with the tab's position and tab count); when several fit, the focused one wins. Outside a WezTerm pane it focuses the first terminal window. `--target-title TITLE` (the Windows `-TargetTitle`) focuses the tab of that title (the tab title, else the pane title, case-insensitive) in whichever window holds it; no such tab is an error. Flags are matched like every other command (`-quiet` works); one it does not know is an error.
- **Usage:** `Focus-TerminalTab [--quiet] [--target-title TITLE] [-v]`

## [Get-WorkspaceBenchmark](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Get-WorkspaceBenchmark)

- **Description:** Shows the rows Open-Workspace appends to `$XDG_STATE_HOME/foundation/WorkspaceBenchmark.csv`, one per workspace open: the mode (Plain, or Alongside for an `--alongside` open), total, launch actions, layout with its wait for windows and arrange, windows found of expected, the layout's attempts (Tries: the most arrange passes one desktop needed, 1 at the first try), the outcome (Applied, Partial, NotFound, NoLayout) and whether `layout-early-move` was on. Oldest first, filtered by workspace, `--last N` (default `benchmark-history` of `workspaces.conf`, 10; `--last 0` shows every row, as `-Last 0` on Windows); closes with a median line per workspace, mode and early-move mode, with its clean runs (Applied at the first try), retries and runs not applied, so plain and alongside opens never mix and the two early-move modes compare directly - read Outcome and the retries before the seconds; `--summary` (as `-Summary` on Windows) for the median lines alone, `--formatted` (`-Formatted`) accepted and ignored since the table is the only output here, `--csv` for the raw rows (not with `--summary`); Measure-WorkspaceOpen rows only with `--include-measured`, or `--source NAME` for the rows of one source (repeatable or a comma list, measured rows included, as `-Source` on Windows; a session id such as `20260101-100000` names its `Measure-WorkspaceOpen 20260101-100000` rows). Rows written before the Mode and Attempts columns read as Plain with no attempt count.
- **Usage:** `Get-WorkspaceBenchmark [WORKSPACE...] [--last N] [--summary] [--csv] [--include-measured] [--source NAME...]` (the Windows-style `--workspace` and `--formatted` are accepted and ignored)

## [Get-WorkspaceState](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Get-WorkspaceState)

- **Description:** Shows the ownership record Open-Workspace writes and Close-Workspace tears down (`$XDG_STATE_HOME/foundation/open-workspaces`): per workspace the windows (app, title, id) and terminal tabs it opened, each marked live or gone as `cw` finds it (a window the app recreated or restarted is live under its new id, `(ID, now NEW-ID)`), so the output is exactly what `cw` would close; every recorded workspace without a name, `--raw` for the record lines (a second instance's key is `NAME#2`). A workspace opened `--alongside` shows `(alongside)` after its name; a workspace open twice shows each instance under its `cw` label (`Name (alongside, desktop 6)`)
- **Usage:** `Get-WorkspaceState [WORKSPACE[,WORKSPACE...]...] [--raw]` (the Windows-style `--workspace` is accepted and ignored)

## [Measure-WorkspaceOpen](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Measure-WorkspaceOpen)

- **Description:** The controlled experiment behind the Open-Workspace speed work (the Windows Measure-WorkspaceOpen): opens one workspace (default Example) many times under alternating settings and compares them. Every run tears down (`--teardown`, default `Kill-All --skip Docker`), waits `--settle-seconds` (5), opens the workspace through the real Open-Workspace with the variant's settings (`FOUNDATION_SETTING_OVERRIDES` - no config file is edited, nothing to restore) and takes the benchmark row that open wrote, stamped `Source` so the everyday Get-WorkspaceBenchmark history leaves it out. Every open records its benchmark row, even with `benchmark off`, and shows none of it (`benchmark-display none`, as Windows sets Display None). Variants: the current settings as Baseline (a setting without a line counts as the base value, `off` and `500`) plus one per `--setting` flipped (default `layout-early-move` off/on and `layout-stable-ms` 500/1000), `--full-factorial` for every combination, or `--variant "NAME:KEY=VALUE,..."`. Interleaved by default (`--order shuffled` with `--seed`, or `sequential`), `--runs` (5) per variant after `--warm-up` (1) uncounted opens, `--max-minutes` budget, `--dry-run` plan. The summary per variant: runs, clean runs (Applied at the first layout attempt), retries (the layout's attempts beyond the first, from the benchmark row's Attempts), runs not applied (any other outcome, a NoRow or Error included), median/min/max total, median clean total, median actions/layout/wait, and against the reference variant (the first, or `--reference NAME`; a name the session does not have warns and falls back to the first, as Windows does) Effect, Spread and a Verdict (Noise inside half the larger spread, else Faster/Slower). Opens are appended to `WorkspaceOpenMeasurements.csv` with their attempt count (a file from before that column gains it on the next run); `--report [SESSION]` replays a summary (the last session by default), `--list-sessions` lists the recorded sessions with their workspace, start, opens, measured opens and variants (the `-ListSessions` of Windows' Get-WorkspaceOpenMeasurement); without a measurement file both are an error. A run whose Open-Workspace fails without a benchmark row is recorded as Error, one that succeeds without a row as NoRow. Refuses a workspace that closes the calling tab or needs a project none was given for, judged on its actions as Open-Workspace runs them (the template expanded, the project scopes applied; a `%SET` layout-set scope is ignored, so a line counts on every layout set), and one whose template does not resolve; Kill-All quits every app, the Claude app included. The Windows spellings (`-Runs 3`, `-WarmUp 0`, `-DryRun`, `-WhatIf`) work for the words before `--`; what follows `--` reaches Open-Workspace untouched.
- **Usage:** `Measure-WorkspaceOpen [WORKSPACE] [PROJECT...] [--runs N] [--warm-up N] [--settle-seconds N] [--setting KEY...] [--full-factorial] [--variant "NAME:KEY=VALUE,..."...] [--order interleaved|shuffled|sequential] [--seed N] [--teardown "CMD"] [--max-minutes N] [--reference NAME] [--dry-run] [-v] [-- OPEN-WORKSPACE-ARGS...]`, `Measure-WorkspaceOpen --report [SESSION] [--reference NAME]`, `Measure-WorkspaceOpen --list-sessions`

## [Open-DnD](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Open-DnD)

- **Description:** Opens a D&D campaign of `Unix/config/dnd.conf` (CampaignResources, menu in file order without a name): Obsidian, the campaign's `pdf` group through Open-Acrobat and its `browser` group through Open-Browser (one of each per campaign, as on Windows; the last line of each wins); `--foundry-vtt` also starts FoundryVTT when it is in `apps.conf`. A campaign given as a number is that entry of the menu, as `-Campaign 2` is on Windows.
- **Usage:** `Open-DnD [CAMPAIGN] [--campaign NAME] [--foundry-vtt]`

## [Open-Project](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Open-Project)

- **Description:** Runs a project's `action` lines from `Unix/config/projects.conf` (VS Code folders, terminal tabs), `{ProjectName}` in a line replaced by the project's name, as on Windows; menu when no project is given. `--run-app` starts the project with Run-Project instead. `--new-window` reaches Open-ProjectTerminals, or Run-Project with `--run-app`. `--alongside` reaches the project actions that take it (Open-ProjectTerminals). `--vscode-workspace NAME` makes every Open-VSCode action open `NAME.code-workspace` through Open-VSCodeWorkspace instead of the project folder (bare, it asks with that menu), as Open-Workspace `--vscode-workspace` does; the other actions run as configured. A comma list names several projects; a flag it does not know is an error and nothing opens. A project given as a number is that entry of the menu, as `-Project 2` is on Windows.
- **Usage:** `Open-Project [PROJECT[,PROJECT...]...] [--run-app] [--new-window] [--alongside] [--vscode-workspace [NAME]]` (the Windows-style `--project` and `--in-same-shell` are accepted and ignored)

## [Open-ProjectSwagger](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Open-ProjectSwagger)

- **Description:** Opens the first project's entry of the `[Swagger]` browser group unless its tab is already open, as on Windows; does nothing without a project or an entry, so a workspace can declare it unconditionally. Whether the tab is open follows a TCP probe of the entry URL's host and port (the backend; without `nc` it counts as up): while the backend answers, Open-Browser's own check decides, which knows this entry's tab (its URL among a Safari or Chromium window's tabs, in Firefox the window Open-Browser recorded for it), so another project's Swagger UI no longer blocks it; while it does not, a window of the browser whose title holds `problem-page-title` of `window.conf` ("Problem loading page" without a line) counts too, so a rerun does not stack error tabs. A Firefox Swagger tab opened by hand is not seen while the backend is up (the Open-Browser Firefox decision). `--browser TOKEN` checks and opens in that browser (Open-Workspace forwards it). The entry's name goes to Open-Browser, which resolves sections before named URLs, so a browser group named like the project would open instead. A flag it does not know is an error and nothing opens.
- **Usage:** `Open-ProjectSwagger [PROJECT[,PROJECT...]...] [--browser TOKEN]` (the Windows-style `--project` is accepted and ignored)

## [Open-ProjectTerminals](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Open-ProjectTerminals)

- **Description:** Opens a project's WezTerm tabs titled `<Project>.<KEY>` (skipping titles already open unless `--force`), placed by the Windows matrix of `--in-same-shell` / `--new-window` (`-InSameShell:$false`) and `--in-same-group` (the default) / `--no-in-same-group` (`-InSameGroup:$false`): same shell and same group puts every tab in this shell's window, same shell without same group each project in a new window of its own, a new window with same group all the call's projects together in ONE new window, a new window without same group every tab in a window of its own. Without `--in-same-shell` or `--new-window` it decides as Windows does: this shell's window when WezTerm has exactly one window and no project tab (a `<Project>.<KEY>` title of any `projects.conf` project) is open in it, else a new window, which keeps project groups apart; `--alongside` keeps the tabs in the alongside open's own window; of two opposite flags the last one wins. `--focus-tab` (FocusTab) picks the tab selected once the call's tabs are open, when they all went into one window (the same-group modes): an index is the tab at that position in the window (`0`, the first, by default, as on Windows), a title the tab of that title (case-insensitive; none is a warning), `origin` the tab this shell runs in. Each tab greets with Show-TerminalGreeting, so it shows fastfetch and, inside a repository, the styled onefetch panel. `onefetch-in-project-terminals off` in `greeting.conf` leaves onefetch out of that first greeting (`c` in the tab still draws it); `--invoke-onefetch` and `--no-onefetch` decide it for one call. Without a project the menu of projects with tabs is shown; a selection is required. `--alongside` opens the tabs as `--force` does, so an alongside workspace gets its own tabs even when another workspace has the same ones. A comma list names several projects; a flag it does not know is an error and nothing opens. A project given as a number is that entry of the menu of projects with tabs, as `-Project 2` is on Windows.
- **Usage:** `Open-ProjectTerminals [PROJECT[,PROJECT...]...] [--project NAME...] [--new-window | --in-same-shell] [--in-same-group | --no-in-same-group] [--focus-tab origin|TITLE|INDEX] [--force] [--alongside] [--invoke-onefetch | --no-onefetch]`

## [Open-Workspace](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Open-Workspace)

- **Description:** Runs a workspace's actions from `Unix/config/workspaces.conf`; arguments bind like the Windows positional parameters, the first word is the workspace and the following words are projects for Open-Project and `{SelectedProjects}` (`w MyWorkspace MyProject`), commas separate several names (`w Dotfiles,AI`). A workspace with a `template` line runs its template from `workspace-templates.conf` with its `set`, `replace`, `drop` and `add` lines applied and `{Workspace}` and the variables substituted; `--VARIABLE VALUE` sets a template variable for one open and is not forwarded, and a template error is reported and opens nothing of that workspace. The open's projects are known before anything launches - the PROJECT arguments, else the project menu shown up front for an `Open-Project` without a project (Enter skips it), else the projects its `Open-Project` lines name - and pick the `+A,B` / `+!A,B` lines that run, fill a bare Open-Project and `{SelectedProjects}`, and reach Set-WorkspaceWindowLayout as `--project`, whose layout variants then apply; an `Open-Project` that names its project keeps it, and every `Open-Project` keeps its own flags (`--run-app`), as on Windows. A `%A,B` line runs only when the layout set this machine applies (`layout-override`, else `small-display`, else the machine type) is A or B, the LayoutMachine of Windows. It records what the open created for Close-Workspace, and runs the deferred actions its openers queued (the slow tail of an action, such as Obsidian's workspace load after a cold start, `foundation_defer` of `lib/foundation.sh`: the Register-DeferredAction / Complete-DeferredActions pair of Windows) just before its layout, so the actions in between do not wait for them, and a failed one is named among the failed actions; it draws deferred terminal panels once the layout placed the windows. Unknown actions are reported and skipped; a `Return` action stops the open where it stands, as on Windows, and before `Terminate-WindowsTerminalTabs --only-current` (or `--include-current`), which closes the tab the open runs in, the record and the summary are written first; `--only-current` is skipped, as on Windows, when that tab is one of this open's own project tabs (`<Project>.<KEY>` of a project its `Open-Project` lines open), so rerunning a workspace from its project tab keeps the tab. Every open ends with `Workspace(s) opened in N seconds!`, an alongside open counting from the original invocation, so the relaunch is included. With `benchmark on` in `workspaces.conf` (off without a line, as WinuX's `WorkspaceBenchmark.Enabled`) it also appends a benchmark row (Get-WorkspaceBenchmark) and shows what `benchmark-display` says: `table` (the default) the workspace's last `benchmark-history` runs, `line` one `Timing [Workspace] =>` line in the Write-WorkspaceBenchmark form (`actions 5.1s | wait 9.3s | arrange 1.2s | other 0.6s`, plus `retries N` when a desktop of the layout had to be arranged again and `outcome Partial 5/6` when not every window was placed); the row carries the open's mode (Plain or Alongside) and the layout's attempts, `none` nothing. Any other flag is forwarded to every action that documents it, like the ExtraArgs of Windows (`w Example -Browser Chrome` reaches Open-Browser only). Without a name it shows the numbered workspace menu (numbers or names, several at once, as with Resolve-Selection on Windows); an empty Enter opens `default-workspace`. A workspace with a `default` line in `Unix/config/vscode-workspaces.conf` (DefaultVSCodeWorkspaces) gets that `.code-workspace` in place of its Open-VSCode folder; `--vscode-workspace NAME` does it for one run, a bare `--vscode-workspace` shows the menu. `--alongside` opens the workspace next to the ones already open, as on Windows: the open is relaunched in a new WezTerm window (the calling shell gets its prompt back; without a running WezTerm it runs in place) whose tabs and window it owns, and the new window clears the relaunch line typed into it (kept out of the shell history too), so it shows only the open's output; its layout lands on the desktops right of the highest one holding a window of another recorded workspace (AeroSpace creates desktops past 10 as needed) and places only the windows the open created, `--alongside` and `--desktop-offset N` reach every action that documents them, and the record marks it alongside. A plain open leaves the windows of a live alongside workspace alone (never claimed, moved, parked or recorded) and keeps its record; a plain open of that same workspace adopts it, replacing every record of that name. An alongside open of a workspace that is already open is a second instance, as on Windows: it leaves the first instance's windows alone, lands after its desktops and is recorded apart (`NAME#2`), so `cw` can close either. macOS runs most apps once, so an app that already has a window keeps it where it is. An action that fails is reported where it fails; the closing line then names the failed actions in a warning instead of the success line, and the exit status stays 0. A workspace given as a number is that entry of the workspace menu (`w 2`), as `-Workspace 2` is on Windows. A named workspace with no section in `workspaces.conf` is reported (`No actions configured for workspace [Name]`) and skipped before anything opens, so an `--alongside` open of it opens no window; when none of the named workspaces exists the open ends there with exit status 1 and no summary line.
- **Usage:** `Open-Workspace [WORKSPACE[,WORKSPACE...]] [PROJECT[,PROJECT...]...] [--project NAME...] [--VARIABLE VALUE...] [--timeout-seconds N] [--vscode-workspace [NAME]] [--alongside] [-v]` (the Windows-style `--workspace NAME...` names the workspace too)
- **Alias:** `w`

## [Start-Containers](https://github.com/IvanPavlak/Foundation/blob/master/Unix/modules/Workflow/bin/Start-Containers)

- **Description:** Brings up Docker Compose stacks of `Unix/config/docker.conf` without running a project (menu, sorted by name, when several exist and none is named) and prints their published ports; every chosen stack's compose file is checked first, an unknown stack or missing file fails that stack only, and Docker Desktop starts only when one remains; `--stop` stops them, `--stop --down` removes containers and network (volumes kept). Docker Desktop stays running. A flag it does not know is an error and nothing starts or stops. A stack given as a number is that entry of the menu, as `-Name 2` is on Windows.
- **Usage:** `Start-Containers [STACK[,STACK...]...] [--stop] [--down]` (the Windows-style `--name` is accepted and ignored)
